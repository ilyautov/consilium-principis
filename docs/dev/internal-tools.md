# Внутренние тулы (intentionally-internal)

Все тулы MCP-сервера (`scripts/mcp_server.py`, словарь `TOOLS`) зарегистрированы и
вызываемы. Но не каждый из них **проводится хосту** — то есть упоминается в
`INSTRUCTIONS` (правила поведения скилла) или в описании тула-родителя, откуда
хост его «увидит».

**Внутренний тул** — это тул, который зарегистрирован и вызываем, но
_намеренно не рекламируется_ хосту. Его вызывают:

- **другой тул** (plumbing) — например, поллер джоба или билд-гейт, которые
  дёргает тул-родитель;
- **мейнтейнер** — ритуалы обслуживания и eval-инструменты, не предназначенные
  для конечного юзера;
- **CLI** — у некоторых есть скриптовый двойник в `scripts/`.

Такие тулы не являются «тёмными»: их отсутствие в `INSTRUCTIONS` — осознанное
решение, а не пробел. Регрессионный гард `tests/test_no_dark_tools.py` следит,
чтобы любой тул был либо проведён хосту (INSTRUCTIONS / описание сиблинга /
рецепт), либо явно перечислен здесь. Если появляется тул, который нигде не
проведён и не помечен внутренним, — гард падает.

## Реестр внутренних тулов

Машиночитаемый список id (по одному в строке) — его парсит гард-тест:

```text
validate_manifest
job_status
ollama_ensure
stability
atomic_grounding
catalog_verify
```

## Почему каждый — внутренний

| Тул | Назначение | Почему не в INSTRUCTIONS |
| --- | --- | --- |
| `validate_manifest` | Build-time МОАТ-гейт: проверяет тир-манифест советника перед сборкой. | Plumbing. Уже назван в описании `build_advisor` («зови ПЕРЕД build-advisor») — виден через тул-родитель, не нужен отдельным правилом. |
| `job_status` | Поллер фоновых джобов по `job_id`. | Plumbing. Уже назван в описаниях `build_advisor` / `seed_council` / `ingest_telegram`, которые возвращают `job_id`. |
| `ollama_ensure` | Поднимает `ollama serve`, чтобы включить FULL-тир. | Plumbing. Покрыт Rule 0 и тулами `setup_full` / `doctor`; ручной шаг — только первая установка бинаря. |
| `stability` | Eval-диагностика стабильности вердикта (robust / leaning / coin-flip). | Eval-инструмент для мейнтейнера, не рабочий шаг совета. |
| `atomic_grounding` | Eval-инструмент: атомизирует заявление и меряет inflation gap (завышение единого score). | Eval-инструмент для мейнтейнера, замеряет ров, а не обслуживает юзера. |
| `catalog_verify` | Ритуал целостности каталога (подпись / PD-basis / дрейф). | Maintenance-ритуал; есть CLI-двойник `scripts/catalog_verify.py`. |
