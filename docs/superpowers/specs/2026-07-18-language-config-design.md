# Языковой конфиг INSTRUCTIONS — дизайн

**Дата:** 2026-07-18
**Статус:** дизайн одобрен устно, ждёт ревью спеки
**Скоуп:** выключатель языка ответа в MCP-сервере Consilium-Principis (дешёвый путь).

---

## 1. Проблема (замерена, не гипотеза)

`INSTRUCTIONS` в `scripts/mcp_server.py` — 20134 символа, 79.7% кириллицы. Хост читает их
один раз при `initialize` (строка ~2208: `"instructions": INSTRUCTIONS`). Замер
2026-07-16 (`scripts/experiments/instructions_language_probe.py`, калибровка чистая, прибор
чувствителен): английский вопрос → 75% ответов по-русски на gpt-4.1, 57% на glm-5.2.
Англоязычный пользователь получает совет на языке, которого не знает — это блокер дистрибуции.

## 2. Что уже сделано (базовый слой — en_bottom)

Плечо `en_bottom` — измеренный победитель A/B пяти плечей — уже добавлено в конец `INSTRUCTIONS`
(блок `RESPONSE LANGUAGE (overrides formatting; never overrides Rule 0). Answer in the language
of the USER'S QUESTION…`). Замер: чинит английский путь (0% кириллицы на gpt-4.1, 9% на glm-5.2)
и держит русский (97% / 86%). **Это автоподстройка под язык вопроса.**

> ⚠️ **Зависимость.** На момент написания спеки en_bottom добавлен в файл, но НЕ закоммичен
> (ship-субагент оставил `mcp_server.py` под правкой + подтверждающий замер). Выключатель
> строится ПОВЕРХ en_bottom — сначала должен приземлиться и быть закоммичен ship-коммит
> en_bottom, только потом реализация этой спеки.

## 3. Что добавляет выключатель (и зачем, раз en_bottom уже двуязычен)

en_bottom = умное автоопределение по языку вопроса. Выключатель = жёсткая фиксация. Нужен там,
где автоопределению нельзя доверять на 100%:

- **Смешанный вопрос.** Англоязычный юзер вставляет русскую цитату/фамилию (`What did X mean by
  «…»?`) — вопрос наполовину русский, модель может свалиться в русский ответ. `CONSILIUM_LANG=en`
  фиксирует английский независимо от языка вопроса.
- **Остаточная примесь.** glm дал 9% кириллицы и 1 пустой ответ на en_bottom. Кому нужна
  гарантия, а не «скорее всего», — фиксирует язык конфигом.
- **Локальный русский режим владельца.** `CONSILIUM_LANG=ru` — гарантированно русские ответы
  для ежедневной работы, без зависимости от языка конкретного вопроса.

## 4. Архитектура (дешёвый путь)

Контур остаётся ОДИН (русский `INSTRUCTIONS` + встроенный en_bottom). Выключатель — короткий
детерминированный блок, который сервер ДОПИСЫВАЕТ к тексту при `initialize` по значению env.
Перевод 20к символов НЕ делается (см. §8).

### 4.1 Источник конфига: env-переменная `CONSILIUM_LANG`

Почему env, а не `board_config.json` и не отдельный тул: в проекте уже есть паттерн
`CONSILIUM_JUDGE_BACKEND` (env), а в MCP env задаётся в конфиге плагина (`.mcp.json`) при
установке. Новый механизм не изобретаем.

Значения (регистр игнорируется, пробелы тримятся):

| Значение | Поведение |
|---|---|
| не задано / `auto` / `""` | базовое en_bottom — ответ на языке вопроса. **Дефолт.** |
| `en` | дописывается форс-блок: всегда английский, независимо от языка вопроса |
| `ru` | дописывается форс-блок: всегда русский, независимо от языка вопроса |
| любое другое | **fail-safe → `auto`** (не роняем сервер, не инжектим мусор) |

### 4.2 Дефолт = `auto`, НЕ `en`

Публичный плагин чинится автоподстройкой (en_bottom) без всякой настройки. Форсить английский
всем — сломать русскоязычного юзера, поставившего из англоязычного каталога. Жёсткая фиксация —
осознанный выбор пользователя, не умолчание.

### 4.3 Точка внедрения: `initialize`

Одна функция `_response_language_directive(lang: str) -> str` возвращает форс-блок или `""`.
В `initialize` (строка ~2208) отдаётся `INSTRUCTIONS + _response_language_directive(cfg)` вместо
голого `INSTRUCTIONS`. Одно место, обратимо.

### 4.4 Тексты форс-блоков

`en`:
```
RESPONSE LANGUAGE OVERRIDE (never overrides Rule 0): the user has configured English output.
Answer ENTIRELY in English — headings, tier labels, service lines — regardless of the language
of any individual question. This overrides the "language of the question" rule above.
```

`ru`:
```
ЯЗЫК ОТВЕТА — ФИКСАЦИЯ (не перекрывает Правило 0): пользователь настроил русский вывод.
Отвечай ЦЕЛИКОМ по-русски — заголовки, лейблы тиров, служебные строки — независимо от языка
отдельного вопроса. Это перекрывает правило «язык вопроса» выше.
```

Оба несут клаузу «(never overrides Rule 0)» / «(не перекрывает Правило 0)» — фиксация языка НЕ
может ослабить безопасность/fail-closed. Блок дописывается ПОСЛЕ en_bottom, поэтому «фиксация»
перекрывает «язык вопроса» позиционно (последнее слово).

### 4.5 doctor

`doctor.py` (`run_doctor` возвращает список чеков `{"name","ok","detail"}`) получает чек
`{"name": "response-language", "ok": True, "advisory": True, "detail": "<auto|en|ru> (CONSILIUM_LANG)"}`.
Диагностика, не источник истины. Источник — env.

## 5. Управление дрейфом (болезнь «правило есть, а не исполняется»)

Форс-блоки короткие и НЕ дублируют Правила 0/5 — значит расходиться нечему (в отличие от полного
перевода, §8). Защита гардами:

- **G1** `CONSILIUM_LANG=en` → отдаваемые instructions содержат англ. форс-директиву; `ru` →
  русскую; `auto`/unset → НИ ОДНОЙ (только базовый en_bottom).
- **G2** во ВСЕХ трёх режимах Правила 0 и 5 присутствуют дословно (форс-блок их не вытесняет).
- **G3** оба форс-блока несут клаузу подчинения Правилу 0 (grep по маркеру) — гарантия, что
  фиксация языка не ослабляет fail-closed.
- **G4 (fail-safe)** мусорное значение `CONSILIUM_LANG` → отдаётся базовый `auto`, сервер не
  падает, мусор в instructions не попадает.
- **G5 (гард не спит)** пустой/отсутствующий форс-блок при заданном языке = падение теста, а не
  зелёное молчание (в этой сессии ловили дважды).
- **Офлайн-инвариант:** `HEPHAESTUS_ENGINE=/nonexistent OLLAMA_HOST=http://127.0.0.1:59999
  python3 -m pytest tests/ -q` остаётся зелёным.

## 6. Тестирование (TDD)

Юнит, без сети:
- `_response_language_directive("en")` содержит английский форс + клаузу Rule 0.
- `_response_language_directive("ru")` содержит русский форс + клаузу Правило 0.
- `_response_language_directive("auto")`, `("")`, `(None)`, `("xyz")` → `""`.
- `initialize` с `CONSILIUM_LANG` (через monkeypatch env) отдаёт instructions с нужным блоком;
  без env — без блока.
- G1–G5 как отдельные тесты.

⚠️ Env-гигиена (мина сессии): `LLM_BACKEND=openrouter` течёт из `test_antisycophancy_probe.py:221`.
Тесты, трогающие env, держать герметичными через `monkeypatch`, не оставлять `CONSILIUM_LANG` в
`os.environ` после теста.

## 8. Явно ВНЕ скоупа (YAGNI)

- **Полный перевод контура на английский.** Две полные версии INSTRUCTIONS дают на релизе
  недоказанную пользу (гипотеза «полный EN бьёт форс-блок» НЕ замерена) и три риска: зеркальный
  слом (как `ru_top` заставил отвечать по-английски на русский вопрос), дрейф Правил 0/5 между
  версиями, ×2 токенов на `initialize`. Отложено до замера: полный EN-контур как ШЕСТОЕ плечо
  `instructions_language_variants_probe.py`, сравнить с en_bottom числами. Послерелизный вопрос,
  не блокер.
- Автоопределение языка по локали ОС, гео, истории. Конфиг явный.
- UI выбора языка. Env + опционально doctor-подсказка.
- Более двух языков. RU/EN — то, что есть в продукте.

## 9. Приватность / firewall

- Слаги приватных советников (их печатает `doctor`) НЕ попадают в код/тесты/доки этой фичи.
- Коммит/пуш — только по явному разрешению владельца (firewall-ритуал).
- Fail-closed и гейт верности не ослабляются (клауза Rule 0 в §4.4, гарды G2/G3).

## 10. Критерий готовности

1. `CONSILIUM_LANG=en` → `initialize` отдаёт instructions с англ. форс-блоком; замер базовой
   пробой: английский путь ≤ порога кириллицы, русский вопрос ТОЖЕ по-английски (это и есть
   смысл фиксации — проверить, что форс реально жёсткий).
2. `CONSILIUM_LANG=ru` → русский форс; оба типа вопросов по-русски.
3. `auto`/unset → поведение en_bottom без изменений (регресс).
4. G1–G5 зелёные, офлайн-инвариант держится, selfdoc свежий.
