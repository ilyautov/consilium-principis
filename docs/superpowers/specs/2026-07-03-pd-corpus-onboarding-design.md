# Спека: PD-онбординг корпуса (каталог + гайдед-сборка совета)

Дата: 2026-07-03. Статус: дизайн утверждён в брейнсторме, ждёт ревью юзера → план имплементации.
Контекст: публичный скилл после установки даёт пустую доску + одну demo-линзу «Стратег». Нужен
**легальный cold-start** — набрать совет из общественного достояния, ни разу не коснувшись копирайта.
Плумбинг на ~80% готов (`collect_pd.py`, `corpusbuild/`, `build_advisor`); эта фича его продуктизирует.

## Цель

Чужой человек, поставив скилл в любом MCP-агенте (Cowork, Claude Desktop, Claude Code, чужой клиент),
называет мыслителя → видит превью-карточку PD-издания → подтверждает → его машина собирает советника
**локально** из общественного достояния. Опытный юзер тем же путём тянет фигуру вне каталога.

## Несущие принципы (инварианты, не обсуждаются)

- **Логика в MCP-сервере**, детерминированная, fail-closed. Хост только предлагает и рисует.
- **Каждый тул stateless.** Состояние диалога держит хост (арендованный ризонинг), серверного
  визарда нет — это то, что делает фичу агент-агностичной.
- **Каталог = указатели, ноль текста.** Мы никогда не перераспределяем текст (даже PD) — только
  линкуем на платформу-источник; её PD-clearance остаётся на ней.
- **Корпус собирается и живёт локально** в `advisors/*` (gitignored) — firewall приватное↔публичное.
- **Verbatim-ров цел.** Никакой ручной правки текста через тулы; только детерминированный
  `apparatus.py`-стрип. Собранный корпус = ровно скачанное+вычищенное, 🔵-гарантия против реального
  источника держится.
- **CLI-фолбэк.** `collect_pd.py` + `build_advisor` работают без MCP вообще (три уровня деградации:
  MCP-тул → CLI → ничего не теряем).

## 1. Каталог — схема

`catalog/pd_figures.json` (шипуется в репо; указатели, не текст):

```json
{
  "version": 1,
  "figures": [
    {
      "id": "marcus-aurelius",
      "name": "Марк Аврелий",
      "seat": "стоик / этика решений",
      "lang": "en",
      "source": {
        "platform": "gutenberg",
        "ref": "2680",
        "edition": "пер. George Long, 1862",
        "url": "https://www.gutenberg.org/cache/epub/2680/pg2680.txt",
        "pd_basis": "Project Gutenberg (US-PD)",
        "expected": { "sha256": "<хэш после apparatus-стрипа>", "min_bytes": 80000, "max_bytes": 130000 }
      }
    }
  ]
}
```

- MVP: ~10-15 пуленепробиваемых фигур. Источники — только `gutenberg` / `standardebooks` (CC0) /
  `wikisource`. Давно умершие авторы, канонические старые переводы.
- `seat` — роль/линза для подсказки состава (не навязывает композицию; это работа `seed_council`).
- `expected.sha256` — сигнатура текста **после** `apparatus`-стрипа (детерминированного) — стабильна,
  пока Gutenberg не переиздал. Дрейф → fail-closed при `catalog_add`.
- Схема валидируется на старте (fail-closed на кривой записи, как no-manifest→A).

## 2. MCP-тулы (тонкая оркестрация поверх готового плумбинга)

Все возвращают render-agnostic объект (§4). Все stateless.

| Тул | Вход | Делает | Мутирующий |
|-----|------|--------|-----------|
| `catalog_list` | — | Список фигур каталога (id/name/seat/edition/pd_basis). Без фетча. | нет |
| `catalog_search` | `author` | Кандидаты-издания из Gutenberg через gutendex.com API (SSRF-guarded fetch). Хвост вне каталога. Оффлайн → честная деградация. | нет |
| `catalog_preview` | `id \| url` | Фетч→`apparatus`-стрип→ `{sample (первые N симв.), apparatus_regions, bytes, sha256, pd_host_ok, warnings}`. **НЕ собирает.** Это consent-карточка. | нет |
| `catalog_add` | `id \| url`, `license?` | Фетч → сверка сигнатуры (если из каталога) → стрип → `build_advisor` pipeline → `advisors/{id}/` локально. | **да (Rule 0)** |
| `catalog_verify` | — | Обходит каталог, тянет каждую запись, сверяет sha256/bytes/pd_basis, репортит дрейф. Ритуал как `moat-check`. + CLI-двойник. | нет |

Реюз: `catalog_add`/`preview`/`search` зовут `collect_common` (SSRF-guarded fetch), `collect_pd`
(стрип+provenance), `corpusbuild/` pipeline, `build_advisor`. Новый код — каталог, 5 тонких тулов,
превью-объект, INSTRUCTIONS-хук, `catalog_verify`.

## 3. Превью render-объект

Один объект → адаптеры рендера (паттерн `session_render`):

```json
{
  "kind": "pd_preview",
  "figure": "Марк Аврелий", "edition": "пер. George Long, 1862",
  "pd_basis": "Project Gutenberg (US-PD)", "bytes": 92160,
  "sample": "…первые ~400 символов вычищенного текста…",
  "apparatus_stripped": ["Gutenberg header (юр. обёртка)", "TOC"],
  "warnings": [],
  "confirm_hint": "Собрать советника локально из этого издания?"
}
```

Cowork рисует виджет-карточку, Claude Code — текстовый блок, чужой агент — свой формат. Тул не знает
и не заботится, кто рисует.

## 4. Поток данных

**Основной (новичок):** «хочу Марка Аврелия» → хост зовёт `catalog_preview("marcus-aurelius")` →
рисует карточку → юзер «ок» → `catalog_add("marcus-aurelius")` → сборка локально → фигура в совете.

**Хвост (опытный):** «хочу Спинозу» (нет в каталоге) → `catalog_search("spinoza")` → кандидаты-издания
с pd_basis → `catalog_preview(url)` → «ок» → `catalog_add(url, license="public-domain")`.

Хост — стейт-машина диалога. Сервер — набор stateless-ответов.

## 5. Ошибки / гейты (всё fail-closed)

- Не-PD-хост без явного `license="public-domain"` → отказ (уже в `collect_pd`).
- Сигнатура при фетче не сошлась с `expected.sha256` (текст уплыл) → **не собираем молча**, громкий
  fail с человеческим объяснением.
- OCR-шум: `catalog_preview` показывает сэмпл (юзер видит качество); базовая эвристика доли не-текст.
  символов → `warnings`.
- `catalog_add` — только с согласия юзера (Rule 0); превью-карточка обязательна перед ним.
- Оффлайн/сеть упала → `search`/`preview` возвращают честную ошибку, не крашат.
- Схема каталога кривая/отсутствует → fail-closed (тул недоступен, не «пустой каталог»).

## 6. Firewall

- В репо едет только `catalog/pd_figures.json` (указатели). Ни текста, ни собранных советников.
- Собранное — в `advisors/*` (уже gitignored). `firewall_check.sh` уже стоит на страже push.
- Спека и каталог — только PD-примеры (Марк Аврелий, Сунь-Цзы, Спиноза, Эпиктет), ноль приватных имён.

## 7. Тестирование (оффлайн, CI-инвариант цел)

Мокаем `collect_common`-фетч фикстурами (никакой сети в CI):
- валидация схемы каталога (хорошая/битая записи);
- `catalog_list` возвращает фигуры;
- форма превью-объекта (`kind`, sample, apparatus_regions, sha256);
- `catalog_add` оркестрация на мок-PD-тексте → советник в tmp-`advisors/`;
- **fail-closed** на дрейфе сигнатуры (мок-текст ≠ expected.sha256 → отказ, не сборка);
- отказ на не-PD-хосте без license;
- `catalog_search` на мок gutendex-ответе (парсинг кандидатов);
- превью-warnings на мок-OCR-шумном сэмпле.

## 8. Scope и фазы

- **MVP (2+):** каталог (~10-15 фигур) + 5 тулов + INSTRUCTIONS-хук + `catalog_verify` (+ CLI-двойник).
- **Отложено (по данным/нужде):** «студийная» ручная чистка (ломает verbatim — НЕ берём никогда),
  стартовые композиции советов, расширение платформ-источников, авто-подбор `seat`.
- Каждая фаза — своя ветка, адверсариальное ревью перед мержем (правило дуги Moat v2), оффлайн-CI.

## 9. Риски / открытые вопросы

- **gutendex.com как зависимость `catalog_search`** — внешний API третьей стороны. Митигация: search
  необязателен (каталог покрывает основной кейс); оффлайн-деградация; при недоступности — прямой URL.
- **PD-статус per-jurisdiction.** Мы наследуем clearance платформы-источника (Gutenberg = US-PD),
  не заявляем сами. Дисклеймер в превью-карточке и README: «PD-статус — по источнику, проверь для
  своей юрисдикции».
- **Сигнатуры в каталоге надо один раз посчитать** (прогнать `catalog_verify --seed` по каждой
  записи) и держать свежими — иначе fail-closed заблокирует легитимную сборку. `catalog_verify` в CI?
- **`seat`-таксономия** — держать свободным текстом в MVP (YAGNI), формализовать если журнал покажет.

## 10. Критерий успеха

Чужой человек в свежем Cowork/Desktop за ≤3 реплики собирает ≥2 PD-советников из каталога и проводит
совет — ни разу не коснувшись копирайта и не увидев CLI. Хвостовой кейс (`search`→`preview`→`add`
фигуры вне каталога) отрабатывает в том же агенте без серверного состояния.
