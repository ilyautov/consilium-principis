# Карта архитектуры (5 частей)

**1. MCP-сервер.** `scripts/mcp_server.py` — реестр тулов + блок
`INSTRUCTIONS` (правила 0–14). Это host-facing контракт: Consilium
поднимается как MCP-сервер контекста и инструментов, а не как модель —
рассуждает вызывающий хост (Claude/GPT), сервер лишь даёт ретрив,
детерминированный гейт верности и счёт. Ключевой факт архитектуры: MCP-хост
видит ТОЛЬКО имена тулов, их `description` и `INSTRUCTIONS` из ответа
`initialize` — он НЕ читает `SKILL.md` (тот виден только в режиме
Claude Code). Поэтому всё поведенческое для MCP живёт в `INSTRUCTIONS` и
описаниях тулов, а `SKILL.md` — их зеркало для CLI-режима.

**2. Движок ретрива и тиров.** `scripts/engine/` — портативный контракт
`Engine` (ABC) с backend-независимыми `abstain_check`/`fidelity_check`;
бэкенды `LexicalEngine` (стандартная библиотека, ноль установки — тир
SIMPLE) и `SemanticEngine` (обёртка `tier_full`, bge-m3 через ollama — тир
FULL), плюс `RemoteEngine`. `resolve_engine` авто-детектит тир по размеру
корпуса советника; `safe_retrieve` даёт деградацию в рантайме. Тир FULL
исторически зависел от внешнего движка Гефеста (`HEPHAESTUS_ENGINE`), но
эмбеддинг-примитив с 2026-06-30 вшит прямо в `tier_full.embed_batch` —
Гефест остался опциональной зависимостью только для reranking.

**3. Сборка корпусов.** Пакет `scripts/corpusbuild/` (сборщики `collect_pd.py`
/ `collect_web.py` / `collect_transcript.py`, чанкинг с тиром, build-lock,
`apparatus.py` для strip'а редакторского аппарата PD-книг) плюс
`build_advisor` — сборка советника в один шаг: манифест-гейт → corpus →
кернелы.

**4. PD-каталог онбординга.** `scripts/catalog.py` + пять тулов
(`catalog_list`, `catalog_search`, `catalog_preview`, `catalog_add`,
`catalog_verify`) — каталог общественного достояния, из которого
пользователь собирает советника или линзу без ручного поиска источников.
Каталог хранит указатели на тексты, а не сами тексты; `catalog_add`
скачивает, авто-стрипает аппарат и сверяет подпись при сборке.

**5. Eval и QA.** Ритуал `make moat-check` (`scripts/moat_check.py`) против
зафиксированного `docs/dev/moat-baseline.json`, судья релевантности
(`relevance_gate.py`/`relevance_judge.py`), стабильность вердикта
(`stability.py`), adversarial-луп и калибровка per-advisor порогов
(`calibrate_advisor.py`) — держат ров измеримым, а не декларативным.

**Поток запроса.** Вопрос пользователя → маршрутизация (правило-гейт: это
решение/спор/справка?) → соответствующий режим (заседание / карта решения /
ситуационная карта) → рендер ВСЕГДА через виджет (Cowork) или markdown
(голый Claude Code), никогда сырой прозой поверх готового рендера.

**Три уровня деградации.** Полный стек — MCP-тул из любого хоста; без
MCP-подключения — тот же функционал через CLI-фасад `scripts/board.py`; без
ollama и семантики — тир SIMPLE (чистый Python, лексика) с тем же контуром
верности. Ничего из этого не теряет честность — деградирует только меткость
поиска.
