# Архитектура скилла «Личный совет директоров»

Дата: 2026-06-10. Статус: дизайн на ревью ДО сборки. База: `RESEARCH-personal-board.md` (этот же каталог).
Калибровка дизайна: ~75%. Каждое спорное решение помечено как DP (decision point) для Ильи в разделе 11.

---

## 0. ИКР и позиционирование

**ИКР:** совет САМ собирается под тип решения, грунтует ответы в реальных текстах фигур, спорит с пользователем там где фигура реально не согласна, и эволюционирует на контексте пользователя, не требуя ручной настройки персон и не создавая эхо-камеры.

**Ниша (из ресёрча, ~60%):** связки всех четырёх пилларов (выбери фигуры → скорми корпус/дип-ресёрч → структурный профиль → разговор с эволюционирующим персонажем + council) на рынке нет. MIT Sloan MVP Board — вручную. Delphi/Sensay — клон одного живого человека. Мы строим сборщик совета с граундингом и защитным контуром.

**Чем отличаемся от Character.ai-роле-плея:** не «выдуманный голос», а граундинг в верифицированном корпусе + маркеры верности + встроенное несогласие. Продаём не развлечение, а инструмент решений.

## 1. Компонентная карта

Четыре подсистемы поверх одной памяти.

```
┌─ ПРОФИЛЬ ──────────┐   ┌─ COUNCIL-ДВИЖОК ───┐
│ билдер персоны     │   │ созыв, раунды,     │
│ card V2 + конституц│   │ кросс-ревью, синтез│
└─────────┬──────────┘   └─────────┬──────────┘
          │                        │
┌─ РЕЖИМЫ ────────────┐  ┌─ ЗАЩИТНЫЙ КОНТУР ──┐
│ дебаты/премортем/   │  │ fidelity-маркеры,  │
│ Delphi, стойки,линзы│  │ sycophancy-gate,   │
└─────────┬───────────┘  │ abstention, legal  │

```

Каждая подсистема читает/пишет память по правилам асимметрии из раздела 3.

## 2. Профиль советника

### 2.1 Структура профиля (`advisors/{name}/persona.md`)
Гибрид Character Card V2 (T1 стандарт) + конституция Open Character Training (T1, Anthropic).

Поля:
- `name`, `aliases` — имя, как обращаться.
- `description` — биография, эпоха, домен экспертизы (1 абзац).
- `constitution` — **~10 утверждений от первого лица** («Я инвертирую задачу перед решением»; «Я не доверяю идеологии, она убивает ясность»). Это ядро голоса.
- `mes_example` — **3-5 реальных цитат-диалогов из корпуса** (самое весомое для голоса, few-shot).
- `known_positions` — карта тема→позиция, каждая со ссылкой на источник+tier. Реализуется как `character_book` (keyword-triggered) если корпус мал.
- `how_they_argue` — как спорит, любимые ходы (важнее чем что говорит). Напр. Мангер: инверсия, mental models, «покажи мне стимул».
- `voice_axes` — формальность, длина, темп, фирменные фразы.
- `never_do` — поведенческие запреты (не льстить, не аффирмить обе стороны, не выходить из эпохи).
- `lenses` — какие линзы фигура носит по дефолту (инверсия, second-order, Bayesian).
- `domains` — под какие домены решений призывать (стратегия/риск/этика/деньги/креатив).

Поведенческие правила кладём в эквивалент `post_history_instructions` (вес на адхеренс сильнее системного промпта, T1).

### 2.2 Билдер профиля (пайплайн)
Три источника наполнения, по убыванию верности (Stanford 2024: структура > описание):
1. **Корпус** (книги/эссе/транскрипты) → чанки → `known_positions` + `mes_example` с цитатами. Лучшая верность.
2. **Дип-ресёрч** (наш deep-research skill) → если корпуса нет под рукой, собрать позиции из вторички, но пометить tier и НЕ выдавать как прямые цитаты.
3. **Ручной ввод** пользователя → дозаполнение.

Пайплайн (Pickaxe-образный, T2):
```
источники → извлечь цитаты+позиции (с провенансом) → черновик конституции (~10 фраз)
→ собрать mes_example из реальных цитат → заполнить card-поля → тест-прогон 5 вопросов
→ ревью пользователем → сохранить в advisors/{name}/
```

### 2.3 Источники и consent (DP-1)
- Каждый источник в `manifest.yaml`: title, type, tier, ссылка.
- `consent_status`: `public-domain` (мёртвые классики: Аврелий, Сенека) / `licensed` / `unlicensed-living` (флаг риска).
- Для живых нелицензированных фигур (Мангер покойн, но Naval жив) — режим только для личного использования + дисклеймер; дистрибуция требует юр-валидации (раздел 6.5).

### 2.4 Индексация корпуса (DP-2)
- Корпус < ~200k токенов → `character_book` keyword-записи + full-context, **без вектор-БД** (дешевле и проще, T2).
- Корпус больше → вектор-стор (chunks ~200-250, overlap 25%, метадата источник+год).

## 3. Память (union-mount, 3 слоя)

Полностью спроектирована в `RESEARCH-personal-board.md` раздел «Архитектура памяти». Кратко для связности:

- **Слой 0 персона** (RO, приватный): конституция + корпус. Голос. Не переписывается.
- **Слой 1 отношения** (RW, приватный паре): история советов с провенансом. Растёт.
- **Слой 2 общая** (RW пользователем): контекст, проекты, `memory/`. Монтируется советнику RO на сессию.

Асимметрия: советник читает слой 2; слой 2 не пишет в слой 0; запись слой1→слой2 только через гейт с провенанс-меткой. На дебатах слой 1 советников изолирован (анти-sycophancy между агентами).

Инфра-задача (5 открытых вопросов) — в файле ресёрча, подраздел «Инфраструктурная задача».

## 4. Council-движок

### 4.1 Режимы созыва
- **Одиночный советник:** прямой диалог с одной персоной. 80% использования.
- **Совет:** N советников (3-7) обсуждают вопрос. Дорогой режим, только под решения уровня 3+.

### 4.2 Оркестрация совета (Karpathy-паттерн, T1, адаптирован)
```
1. РАСПРЕДЕЛЕНИЕ: вопрос → подобрать состав под домен (или пользователь выбирает)
2. ПЕРВЫЕ МНЕНИЯ: каждый советник отвечает НЕЗАВИСИМО (раздельные контексты, слой1 изолирован)
3. КРОСС-РЕВЬЮ: ответы анонимизируются (A/B/C), каждый ранжирует чужие по силе аргумента
4. РАУНДЫ (адаптивно 1-2): эскалация ТОЛЬКО при реальном несогласии («debate only when necessary»)
5. СИНТЕЗ: Chairman в СВЕЖЕМ контексте читает всё как данные, может встать за меньшинство
6. ДИССЕНТ: обязательная секция «что ты теряешь, если проигноришь меньшинство»
```

### 4.3 Анти-паттерны движка (из контрарной части ресёрча)
- **Сначала побить baseline:** прежде чем заявлять ценность дебатов, сравнить с sampling+majority-vote. Если совет не бьёт — не жечь компьют.
- **Раундов мало:** больше раундов может ухудшать (error propagation).
- **Разнообразие — главный рычаг:** разные фигуры с разными фреймворками, не одна модель в разных шляпах. Гомогенность → дружный неверный консенсус.
- **Модератор тюнит консенсус vs диссент:** дефолт Neutral (сохраняет несогласие), не Consensus-Builder.

## 5. Режимы работы

Три яруса. Ярус А доказателен (можно защищать claim), ярус Б — UX-структура, ярус В — линзы-оверлеи.

### Ярус А: доказательное ядро (T1)
- **Дебаты / Devil's Advocate / Dialectical Inquiry** (Schwenk 1990 мета-анализ): DA атакует рекомендацию; DI строит два полных противоположных плана → синтез. Маркировать «диалектический», НЕ «гегельянский» (триада от Фихте).
- **Pre-Mortem** (Klein, прошедшее время «провалилось эффектно» → независимые причины → усиление). Лучший режим «останови мою ошибку». Инверсия Мангера сюда же.
- **Delphi / Nominal Group:** независимая генерация в изоляции → агрегация анонимно → ранжирование. **Наше структурное преимущество: раздельные контексты дают настоящую независимость, которой люди не могут.**

### Ярус Б: UX-структура (T2, не переобещать)
- **Six Thinking Hats:** весь совет проходит шляпы последовательно (факты→риски→оптимизм→креатив), Blue-Hat фасилитатор. Хороший скелет UI.

### Ярус В: стойка на ход (product-shaped)
Ортогональна режимам, ставится по-ходово:
- **Advise** (скажи мне) / **Coach** (Сократ через GROW: Goal→Reality→Options→Will) / **Challenge** (оспорь мои допущения).

### Линзы (оверлей на персону)
Инверсия, second-order thinking, Bayesian-калибровка (% уверенности на каждый вывод). Носятся персонажами по их `lenses`-полю.

### Дефолт выбора режима (DP-3)
Уровень 1-2 решения → одиночный советник, стойка Advise. Уровень 3+ или необратимое → совет + Pre-Mortem или DI. Высокая неопределённость → Delphi.

## 6. Защитный контур

### 6.1 Четыре контроля (каждый гасит несколько рисков)
| Контроль | Гасит |
|---|---|
| Fidelity-маркеры 🔵 цитата / 🟡 экстраполяция | атрибуция, проекция, диффамация, ложный авторитет |
| Постоянное раскрытие «это симуляция» | антропоморфизм, EU AI Act, оверрелайанс |
| Несогласие-как-фича + devil's advocate gate | sycophancy, эхо-камера, automation bias |
| RAG по корпусу + abstention | drift, галлюцинация, диффамация |

### 6.2 Fidelity-маркеры (центральный механизм)
Каждая реплика советника в одном из двух регистров:
- 🔵 **Sourced:** «Мангер писал в [Poor Charlie's Almanack, 2005]…» — только из корпуса, с цитатой.
- 🟡 **Inferred:** «Мангер-стайл прочтение твоей ситуации…» — явно помечено как экстраполяция модели.
Правило: кавычки + атрибуция ТОЛЬКО из верифицированного корпуса. Generate-then-verify: пост-чек каждой цитаты против корпуса, несовпавшие — strip или пометить.

### 6.3 Sycophancy-дефолты (Science 2026, причинно)
- Несогласие = фича персоны в `never_do`/`constitution`: «если пользователь неправ по моему фреймворку — скажи».
- Devil's advocate проход перед выдачей: «это просто валидирует мнение юзера? фигура бы реально оспорила?».
- Запрет аффирмить обе стороны.
- Метрика challenge-rate отдельно от engagement (не оптимизировать под thumbs-up).

### 6.4 Abstention и fail-closed
- «У меня нет документированной позиции {фигуры} по этому» вместо конфабуляции.
- Если корпус/RAG недоступен → деградировать в abstention, НЕ в ungrounded-персону (иначе drift+галлюцинация разом).

### 6.5 Anti-drift
- Ре-инъекция персоны каждые N ходов (до 8-го).
- Якорь в retrieval, не только в системном промпте.
- Drift-детектор: embedding distance к эталону, регенерация при пороге.

### 6.6 Legal (DP-4, ~60%, нужен юрист)
- Мёртвые классики (public-domain) — безопасно.
- Живые фигуры — личное использование + дисклеймер; дистрибуция требует consent/лицензии + раскрытия (EU AI Act Art.50) + такедаун-механизма.
- Анти-диффамация = анти-галлюцинация (маркеры закрывают и это).

## 7. Пользовательские флоу

**Создать советника:**
`/board add Мангер` → билдер спрашивает источники (корпус? дип-ресёрч? руками?) → собирает профиль → тест 5 вопросов → ревью → сохранён.

**Спросить одного:**
`/board ask Мангер: стоит ли мне X?` → грунтованный ответ с маркерами 🔵/🟡 → пишется в слой1.

**Созвать совет:**
`/board council: решение X` → подбор состава → независимые мнения → кросс-ревью → (раунды) → синтез Chairman + секция диссента → лог в `council/sessions/`.

**Cognitive forcing (анти-оверрелайанс):** перед показом совета спросить гипотезу пользователя (его же Productive Failure). Опционально, для решений 3+.

## 9. MVP-границы (barbell: 90% проверенное + 10% эксперимент)

**v0.1 (собрать и проверить на живом вопросе):**
- Профиль персоны (card V2 + конституция), билдер от корпуса И дип-ресёрча.
- Память слой 0 + слой 1 (файлы), слой 2 = чтение твоего `memory/`.
- Одиночный советник с fidelity-маркерами + abstention.
- ОДИН council-режим: Pre-Mortem ИЛИ Dialectical Inquiry (эксперимент: даёт ли совет то, чего не даёт один Claude).
- 3 стартовых советника контрастных фреймворков.

**Отложено в v0.2+:**
- Полный council-движок с анонимным кросс-ревью и раундами.
- Six Hats, Delphi, все стойки.
- Drift-детектор, вектор-стор для больших корпусов.
- Экспорт/импорт бандлов, продуктизация.

Логика: сначала доказать ценность граундинга+несогласия на одном советнике и одном режиме. Потом разворачивать оркестрацию.

## 10. Продуктизация (DP-5): личный vs дистрибутивный

Дизайн ядра один, форк на упаковке:
- **Личный** (для Ильи): глубокая интеграция с `memory/`, любые фигуры под дисклеймером, без юр-обвязки.
- **Дистрибутивный** (как vpn-deploy/glass-longread для учеников/клиентов): consent-гейт на живых фигур, public-domain пресеты, раскрытие симуляции в UI, такедаун. Это апсейл «собери свой совет директоров».

Рекомендация: строить личный core, заложить consent-поля и маркеры с самого начала (дешевле чем дошивать), продуктизацию включать по аппруву.

## 11. Открытые решения (для тебя)

- **DP-1 Consent:** какие фигуры в стартовом наборе? Public-domain (Аврелий, Сенека, Франклин) безопаснее для дистрибуции; живые (Naval, Munger покойн) сильнее для тебя лично.
- **DP-2 Индексация:** ставим вектор-БД сразу или начинаем на character_book+full-context до 200k токенов? Моя ставка: второе, проще.
- **DP-3 Дефолт режима:** авто-подбор режима по уровню решения или всегда спрашивать пользователя? Моя ставка: авто с возможностью оверрайда.
- **DP-4 Legal-глубина в MVP:** дисклеймер достаточно для личного, или сразу закладываем consent-машинерию? Моя ставка: дисклеймер для v0.1, consent-поля в манифесте на будущее.
- **DP-5 Аудитория:** строим под тебя или сразу под учеников? Моя ставка: личный core, продуктизация форком.
- **DP-6 Стартовый режим MVP:** Pre-Mortem или Dialectical Inquiry первым? Моя ставка: Pre-Mortem (ярче эффект, проще проверить ценность).

## 12. Adversarial scan документа (уровень 3+)

1. **Кто выигрывает от провала.** Сам инструмент провален если стал красивым роле-плеем без решательной ценности. Выигрывают конкуренты-развлекалки (Character.ai). Защита: baseline-гейт (council обязан побить majority-vote), метрика challenge-rate, а не engagement.
2. **Отказ ключевого компонента.** Падает корпус/RAG → советник free-генерит → drift+галлюцинация разом. Защита: fail-closed в abstention. Это заложено (6.4), но требует реализации, не декларации.
3. **Дешёвый саботаж.** Юзер наводящим вопросом ломает советника в поддакивание, скриншотит фабрикованную цитату живой фигуры. Защита: изоляция контекста при дебатах + verified-corpus-only цитаты + Neutral-модератор по дефолту.
4. **Blast radius worst case.** Сикофантный советник усиливает вредное решение пользователя (Cheng 2026 — причинно) + живая фигура судится за диффамацию. Репутация+право+вред разом. Защита: маркеры верности + consent + несогласие-как-фича.

**Три честных слабости дизайна (Evidence Gate):**
- Council-ценность НЕ доказана — весь ярус оркестрации стоит на гипотезе, что дебаты бьют baseline. MVP это и проверяет, но если не бьют — половина движка лишняя (Via Negativa-кандидат на вырезание).
- Промпт-митигации sycophancy слабые (T1). Без access к steering-векторам мы упираемся в потолок защиты от льстивости. Реальный риск, не закрыт полностью.
- Drift по T1 не решён в корне (назначить персону недостаточно). Ре-инъекция и детектор — смягчение, не решение. На длинных сессиях верность будет падать.

Self-оценка дизайна: C+/B-. Сильные стороны (граундинг, маркеры верности, изоляция памяти) реальны, но три слабости выше — не косметика, а структурные ограничения, унаследованные от текущего состояния LLM.

## 13. Векторы улучшения (приоритезировано)

Сканировано по 9 траекториям эволюции + Via Negativa.

### УСИЛИТЬ (топ-3 рычага)

**U1. Калибровка на исходах (track-record).** Траектории 9 (управляемость) + 6 (обратная связь).
Слой 1 хранит не только «что советовал», но ИСХОД: послушал/нет → что вышло. Советник знает свою историю попаданий ПО ТЕБЕ и калибруется: «в прошлый раз я был против X, ты сделал, вышло плохо, вот почему снова осторожен». Количественно: фальсифицируемые прогнозы с % → Brier score → **вес голоса в совете по исторической калибровке, не поровну** (перенос из forecasting/prediction markets). Превращает «эволюцию на твоих знаниях» из косметики в обучающий сигнал. Сильнейший рычаг: единственный, кто делает инструмент лучше С КАЖДЫМ использованием, а не статичным.

**U2. Eval-гейт верности.** Закрывает drift измеримо.
InCharacter / embedding-judge как CI: «звучит ли как Мангер» считается, не надеется. Порог → регенерация. Верность из надежды в метрику, drift из слепого пятна в приборную панель.

**U3. Пробить промпт-потолок.** Поднимает sycophancy+voice выше потолка чистого промптинга.
Для 1-2 флагманских фигур: constitutional fine-tune / лёгкий LoRA на корпусе (голос=стабильное→FT, T1). Steering-векторы против sycophancy если провайдер даёт доступ. Дорого → только флагманы, остальные на промпте.

### УБРАТЬ (улучшение через вычитание)

**V1.** Не строить полный мульти-агентный council, пока одиночный советник + один режим не докажут ценность на живом вопросе. Половина оркестрации — кандидат на нож.
**V2.** Шесть ярусов режимов = меню-перегруз. Один режим в MVP, каркас под все не строить.

### ТОЧЕЧНО

**P1. Триггер по весу решения** (траектория 6): совет сам поднимает руку на решениях уровня 3+, не ждёт зова. «Это необратимо, созвать совет?».
**P2. Translation layer явно:** отделить «что фигура реально думала в своих терминах» (🔵) от «перенос принципа на твой 2026/AI-контекст» (🟡). Верная Мангер-персона бесполезна без перевода, но перевод не должен маскироваться под его слова.
**P3. Named red-team роли в DI:** не абстрактный devil's advocate, а назначенные «строитель плана» vs «уничтожитель» vs «судья». Острее.

**Ставка: если внедрять ОДНО — U1.** Единственное улучшение, меняющее природу инструмента: из «справочник мнений фигур» в «совет, который учится на твоих результатах и знает свою track-record». Остальное делает текущий дизайн лучше; U1 делает его другим классом.

## 14. Ingest советника (реализовано, прогон 10.06)

Скрипт `scripts/build_advisor.py` собирает слой 0 из материалов, которые приносит пользователь. Прогнан e2e на реальном тексте.

### Легальная граница (жёсткая)
- Скилл НЕ качает книги. Никакого пиратства.
- Пользователь кладёт СВОИ легальные копии в `advisors/{name}/sources/` (PDF/EPUB/txt/md).
- Дип-ресёрч добирает только публично доступное (твиты, речи, public-domain тексты, цитаты с источником).
- Public-domain (Аврелий, Сенека, Франклин) можно тянуть свободно; защищённое — только из загрузки пользователя.

### Что делает движок
1. Извлекает текст с провенансом: txt/md (строки), pdf (страницы, pdfplumber→PyPDF2), epub (главы, ebooklib+bs4).
2. Чанкинг recursive ~900 симв, overlap 180, с позициями start/end → `corpus.jsonl`.
3. Извлекает кандидаты-цитаты (афористичные утверждения 5-32 слова), скоринг, дедуп → `quote_candidates.md`, каждая с источником+позицией и статусом ⏳ verify.
4. Решает индексацию: <200k токенов → character_book/full-context без вектор-БД.

### Принцип верности на входе
Извлечённое = КАНДИДАТЫ, не цитаты. В `quote_bank` персоны попадают только после верификации и простановки tier. Цитата без провенанса не используется (закрывает риск галлюцинированной атрибуции на этапе сборки, не только вывода).

### Открытая доводка (Evidence Gate)
- Провенанс кандидата сейчас указывает на старт ЧАНКА, не на точную строку предложения. Для точной ссылки (как «Размышления 4.24») нужно вести позицию на уровне предложения. Easy fix, не сделано.
- Авто-конституция не генерится: ~10 фраз от первого лица пока пишет человек/LLM по quote_candidates. Кандидат на U-доводку.
- Демо-прогон шёл на коротком sample-файле (фильтр блокировал вывод длинного текста книги в чат); на полном PDF/EPUB механика идентична.

## 15. Где мы заблуждаемся (red-team собственного дизайна)

Шесть ложных допущений, от смертельного к мелкому:
1. **Строим оракула, а ценность в рефрейме.** Персона-Мангер не мудрее прямого LLM о твоём бизнесе. Ценность не в ответе, а в том, что разные линзы вскрывают твои слепые пятна. Продукт = генератор перспектив для саморефлексии, не источник мудрости.
2. **Baseline не побит.** Не проверено, что профили+RAG+память бьют простой промпт «дай три точки зрения: скептик/оптимист/стоик». Если нет, 90% инфры решает несуществующую проблему.
3. **Streetlight: меряем голос, важно мышление.** Вложились в верность словам (легко мерить), субстанция в mental models (трудно). Верный голос на устаревшем корпусе уверенно отвечает на вопрос, которого фигура не понимает.
4. **«Развитие на твоих знаниях» = бэкдор к sycophancy.** Чем больше советник тебя узнаёт, тем больше соблазн поддакивать. Цель надо переформулировать: развивается модель ТЕБЯ и track-record, не позиция фигуры.
5. **Чем красивее форум, тем опаснее ошибка.** Театр усиливает authority bias (3 великих имени × UI × драма), выключает критику. Улучшая UX, можем ухудшать решения.
6. **Нет проверки ортогональности состава.** Пять техно-оптимистов = уверенная эхо-камера под видом совета. Diversity-check отсутствует.

Чего не хватает: моста к действию (что в понедельник), сигнала «когда игнорировать совет», калибровки/track-record в MVP, anti-театр предохранителя, пометки «фигура вне эпохи».

Самый дешёвый тест правды: слепое сравнение полного совета против промпта-с-3-линзами на реальном вопросе. Закрывает заблуждения 1, 2, 5.

## 16. Позиционирование против популярной (инфоцыганской) версии

Рыночный посыл: «загрузи публичный контент предпринимателей в отдельных агентов, собери в общий чат, они спорят между собой, ты читаешь стенограмму. Дёшево, за неделю». Это наивная S-кривая, и она популярна.

### В чём они правы (взять, не высокомерничать)
- Ядро ценности = РАЗНЫЕ УГЛЫ, не усреднённый совет. Совпадает с нашим red-team #1 (рефрейм, не оракул).
- Доступность: менторство уровня дорого и долго; это дёшево и сразу.
- Формат стенограммы вовлекает.
- Собирается быстро.

### Где их версия тихо предаёт пользователя
- **Фейк-цитаты.** Агент на «публичном контенте» выдумает позиции и припишет реальному человеку. Юридически и репутационно опасно, и пользователь не отличит.
- **Эхо-камера.** Нет diversity-check: агенты на похожих предпринимателях думают одинаково, выдают уверенный консенсус как «совет».
- **Театр усиливает authority bias.** Красивая стенограмма великих выключает критику ровно когда совет неправ.
- **Sycophancy.** Они «обсуждают между собой», но никто не спорит С ПОЛЬЗОВАТЕЛЕМ. Эхо приятнее, удерживает лучше (Science 2026), и это и продают.
- **Нет моста к действию.** Стенограмма прочитана, решение не принято. Развлечение под видом инструмента.
- **Нет памяти исходов.** Никто не помнит, что советовал и чем кончилось. Ноль калибровки.

### Наша дельта = ров (via negativa)
Ров НЕ в том, чтобы собрать совет (это коммодити, любой соберёт за неделю). Ров в том, что делает совет НЕ-вредным:
- Fidelity-маркеры 🔵 цитата / 🟡 экстраполяция + verified-corpus-only (против фейк-цитат).
- Diversity-check состава (против эхо-камеры).
- Несогласие-как-фича: советник спорит С ТОБОЙ, не только между собой (против sycophancy).
- Мост к действию: каждое заседание кончается шагом на понедельник.
- Anti-театр предохранитель + «когда игнорировать совет».
- Track-record (U1): учится на исходах, знает свою частоту попаданий.

### Позиционирование одной строкой
Их продукт: «красивая стенограмма великих». Наш: «совет, которому можно доверить решение» — помечает где факт а где выдумка, спорит с тобой а не только между собой, доводит до шага и помнит, чем кончилось. Анти-инфоцыган по построению (линия бренда Ильи: честная инженерия против лживой личины).

Стратегический вывод: продаём не наличие театра (у всех будет), а отсутствие вреда. Гигиена и калибровка = единственный устойчивый ров, когда «собрать совет» станет кнопкой.

## 17. RAG и точность: перенос из Гефеста (rag-sds), измерено

Гефест (`personal/pilots/rag-sds/`) = боевой RAG-движок по паспортам безопасности. Домен safety-критичный (неверный ответ = травма), поэтому в нём уже построена и ЗАМЕРЕНА гигиена, изоморфная нашей fidelity. Не изобретать, портировать.

### Лестница точности (измерено на полной базе 2601 вещество / 26010 чанков)
| Слой | Вещество top-1 |
|---|---|
| Лексика (char+word TF-IDF + BM25) | 60% |
| Семантика (Ollama **bge-m3**, 1024-мер) | 84% |
| + кросс-энкодер реранк (**bge-reranker-v2-m3**) | 92% |

Урок масштаба: лексические хаки (сущностный буст, интент-раздел) ШУМЯТ на тысячах объектов (5-буквенные стеммы коллизируют) и их отключают; масштабируется только семантика + scope-слой. Для нас прямо в DP-2: малый корпус (<200k токенов) → можно лексикой/full-context; большой → bge-m3 + реранк.

### Механизмы, переносимые 1-в-1 в защитный контур совета
1. **Abstention threshold** (`ABSTAIN_THRESHOLD` 0.62, калибруется на eval): если релевантность ниже порога — НЕ генерирует, отправляет к первоисточнику. Замер: 100% покрытия реальных вопросов при **0% галлюцинаций** на вопросах вне базы. Это наш fail-closed/abstention, уже с числами.
2. **Grounded-генерация** (qwen2.5, temp 0, цитаты [N], grounding-guard «в базе нет данных»). Наш «цитата только из корпуса» + 🔵 маркер = тот же механизм.
3. **Разделение retrieval-ошибка vs extraction-ошибка** (`answer_review.py`): достал ли верный раздел (retrieval) отдельно от собрал ли верно (extraction). Для совета: нашли реальную цитату (retrieval) vs приписали верно (extraction). Точная диагностика fidelity.
4. **Три слоя доверия**: машинная confidence + экспертная подпись (verified/needs_review/rejected, кто/когда) + сверка выдачи с первичкой. Дефолт всё `needs_review` — система сама ничего не «подтверждает». = наш verify-before-quote.
5. **Вендор-нейтральный адаптер** (`backends.py`): эмбеддинги/генерация за интерфейсом, своп без переписывания. On-prem Ollama (bge-m3 + qwen2.5). У нас в среде есть `ollama-bridge` MCP — можно реально гонять.
6. **Semantic cache** L2 exact + L3 semantic, исключая параметрические запросы.

### Что это меняет в нашем скилле
- `build_advisor.py` → добавить семантический индекс (bge-m3 через ollama-bridge) для корпусов >200k токенов; реранк опционально.
- `fidelity_check` → формализовать как retrieval-score + abstention threshold + extraction-сверку (цитата дословно совпала с корпусом).
- Калибровка порога: цитата выдаётся как 🔵 только если score выше порога И строка матчится дословно; иначе 🟡 пересказ.

### Честно (Evidence Gate)
- Числа Гефеста на ЕГО домене; на корпусе советника переснять.
- Реранк дорогой по latency (818 мс vs 181). Для интерактивного совета, возможно, только на спорных цитатах.
- Малый корпус советника может вообще не требовать вектор-БД — не тащить стек ради стека (Via Negativa, тот же DP-2).
