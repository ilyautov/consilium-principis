# Личный совет директоров (AI-советники-персонажи): исследование

Дата: 2026-06-10. Контекст: проектирование Cowork-скилла, где пользователь выбирает фигуры, скармливает их материалы / запускает дип-ресёрч, строит профили, и работает с ними как с развивающимися персонажами-советниками.

Tier-маркировка источников: **T1** = рецензируемое / официальная дока / первичный автор. **T2** = репутабельный блог/индустрия. **T3** = маркетинг/агрегатор/форум.

---

## TL;DR (моя ставка, калибровка ~80%)

1. **Концепция не нова, но связки из всех 4 пиллар-ов нет на рынке.** Закрытый сборщик «выбери фигуры → скорми корпус/дип-ресёрч → структурный профиль → разговор как с эволюционирующим персонажем» не нашёлся ни у кого. Ближайшее: MIT Sloan «MVP Board» (вручную) и Delphi/Sensay (клон одного живого человека). Это реальная ниша (~60%).
2. **Главный враг встроен в фундамент: sycophancy.** Не баг тюнинга, а структурная ловушка RLHF. Причём именно льстивая версия и есть та, что нравится пользователю и удерживает (Science 2026, причинно). Защита от эхо-камеры должна быть дефолтом архитектуры, а не фичей.
3. **Мульти-агентные дебаты часто НЕ помогают.** Куча T1-работ показывает: дебаты дают прирост в основном за счёт ансамблирования (которое дешевле берётся majority-vote), лишние раунды могут УХУДШАТЬ результат, а гомогенные агенты сваливаются в общий неверный консенсус. Council оправдан только при реальном разнообразии фигур + модератор/судья + мало адаптивных раундов.
4. **Технический шаблон уже существует** (Pickaxe Munger pipeline + Stanford Generative Agents + Open Character Training). Собирается из готовых кирпичей.
5. **Один дизайн-ход гасит сразу 4 риска: маркеры верности** (🔵 цитата из корпуса vs 🟡 экстраполяция модели). Это то самое разделение «верность ↔ адаптивность», что мы обсуждали.

## Ось 1. Что уже делали (существующие практики)

**Концепция «личного совета директоров»** — Jim Collins, T1. Происхождение реальное: начало 80-х, ментор Bill Lazier как «почётный председатель» личного совета. ~7 человек, «кого глубоко уважаешь и не хочешь подвести». Принцип: отбор по характеру, не по достижениям; члены могут не знать, что они в совете.
https://www.jimcollins.com/media_topics/WhatIsImportant.html

**MIT Sloan «MVP Board» (Vipin Gupta)** — T1, ближайший концептуальный блюпринт. Построил виртуальный совет в ChatGPT: персоны по Джобсу, Нуйи, Манделе. Метод воспроизводим: (1) определить домены, где нужна стабильная перспектива (стратегия, инновации, этика, системность, сторителлинг); (2) подобрать иконы под каждый; (3) задать «виртуальные идентичности с ролями, мышлением и challenge-промптами»; (4) совет НЕ статичен, голоса ротируются. Прямо валидирует «эволюционирующих персонажей».
https://sloanreview.mit.edu/article/how-i-built-a-personal-board-of-directors-with-genai/

**Charlie Munger bot (Pickaxe)** — T2, ближайший технический блюпринт. Из «Poor Charlie's Almanack» + транскрипты. Пайплайн: PDF → чанки ~250 слов → OpenAI embeddings в вектор-БД → persona-промпт (тон, темы, стиль речи, длина) → RAG фильтрует факты ЧЕРЕЗ персону. Различают «объективно реальное» (retrieval) и «субъективно реальное» (голос). 25k+ использований (vendor claim).
https://pickaxe.co/post/how-to-use-books-and-documents-to-make-a-chatbot-building-a-charlie-munger-chatbot

**Ask Naval** — T3 продукт / T2 стек. Naval по твитам/интервью/Almanack. Открытая реализация: OpenAI API + Streamlit + LangChain + Chroma (канонический RAG-стек). https://asknaval.ai/

**Delphi.ai** — T2 (VentureBeat) + T3. «Цифровые умы»: загружаешь от 4 до тысяч документов, модель учится на ТВОЁМ материале; голос через ElevenLabs; деплой web/Slack/телефон. Маркетит клонирование «живых или мёртвых». https://venturebeat.com/ai/you-can-now-make-an-ai-clone-of-yourself-or-anyone-else-living-or-dead-with-delphi

**Character.ai** — T2. Юзер-персоны реальных фигур (Эйнштейн, Сократ, Марк Аврелий). Дисклеймер «всё выдумано». НЕ grounded по дефолту. Полезен как UX-референс, не fidelity-референс.

**Stoic / Marcus Aurelius боты** — T3 (chatstoic.com, marcusaurelius.ai в Telegram, freemium). Существование-пруф спроса.

**Council AI (council-ai.app)** — T3. 30+ моделей спорят и приходят к консенсусу. Мульти-МОДЕЛЬ, не мульти-персона, но оркестрация переносима.

**Jamout «AI Council»** — T3, но чистый паттерн: 5 советников с разными стилями + «Chairman» синтезирует в один вердикт. Роли: один ищет failure modes, один спрашивает «ту ли задачу решаешь», один ищет скрытый апсайд, один даёт внешний взгляд, один говорит что делать в понедельник.
https://www.jamout.ai/blog/how-to-build-an-ai-council-in-claude-5-advisors-that-give-you-10x-better-answers

**Stanford «Generative Agents» (2023)** — T1, UIST'23. 25 агентов в песочнице; архитектура observation → planning → reflection + memory stream. Канонический референс для ЭВОЛЮЦИИ персонажей. https://arxiv.org/pdf/2304.03442

**Stanford «Generative Agent Simulations of 1000 People» (2024)** — T1, код открыт. Агенты из 2-часовых интервью 1052 человек воспроизвели ответы людей на 85% точности самих людей. Ключ для тебя: **структурированное интервью корпуса > описание персоны** для верности; интервью-граундинг снижает demographic bias. https://arxiv.org/pdf/2411.10109 · https://github.com/joonspk-research/genagents

> Сборка: Pickaxe RAG (граундинг) + Stanford memory/reflection (эволюция) + Sloan domain-mapping (состав совета) + Jamout Chairman (синтез).

**Не подтвердилось:** «Boardy» (имя занято несвязанным нетворкинг-продуктом), «Council of Foms» (не найдено). Не цитировать.

## Ось 2. Как строится технически

**RAG поверх корпуса.** Чанкинг: recursive + semantic как дефолт для прозы (афоризмы/аргументы рвут границы предложений). Конкретная спека из PersonaAI (T1, arXiv 2503.15489): recursive char chunking, ~200 символов, 25% overlap, иерархия paragraph→line→space→char, метадата на каждый чанк (источник, год, спикер, embedding).
**Тактики против галлюцинаций цитат:** (1) grounding chain-of-thought «сначала найди утверждение в источнике, процитируй, потом отвечай»; (2) жёсткий констрейнт «отвечай ТОЛЬКО из контекста ниже»; (3) inline-цитата `[источник: книга, год]`. (T1 Anthropic docs + T2).
**Важный трейд-офф (количественно):** корпус < ~200k токенов → full-context + prompt caching дешевле и проще, вектор-БД НЕ нужна. Многие корпуса эссе/цитат туда влезают.

**Character Card V2 (SillyTavern)** — T1, де-факто стандарт спеки персоны. Поля: `description`, `personality`, `mes_example` (САМОЕ важное для голоса — few-shot реальными цитатами), `system_prompt`, `post_history_instructions` (инструкции ПОСЛЕ истории — вес на адхеренс СИЛЬНЕЕ системного промпта), `character_book` (lorebook = keyword-triggered знания = прото-RAG без вектор-БД, идеально для «известных позиций»). https://github.com/malfoyslastname/character-card-spec-v2

**Constitutional persona** — T1, самый сильный финдинг. «Open Character Training» (Hubinger et al., Anthropic, arXiv 2511.01689, ноя 2025). Конституция = **~10 утверждений о характере от первого лица для роль-плея** («Я инвертирую задачу перед решением»; «Я не доверяю идеологии, она убивает ясность»). Fine-tuned версия робастнее к adversarial-промптам, чем системный промпт, и почти не роняет общие способности. ⚠️ робастность — про fine-tuned вариант; чистый промптинг этого бонуса не даёт, но конституция-как-системный-промпт всё равно лучшая структура. https://github.com/maiush/OpenCharacterTraining

**Fine-tune vs RAG vs prompt.** Эвристика: «волатильное знание → retrieval, стабильное поведение → fine-tune». Голос = стабильное (FT-территория), факты/позиции = волатильное (RAG). Идеал гибрид: конституция/FT для голоса + RAG для позиций/цитат. (⚠️ маппинг «голос→FT» — обоснованная гипотеза ~75%, не прямая цитата.)

**Память (эволюция).** MemGPT (T1): слоистая память, RAM (контекст) ↔ disk (вектор-store), агент сам пейджит. MemoryBank: каждый ход → «наблюдения» (факты о собеседнике) с провенанс-ссылками на породившие реплики. **Дизайн для скилла: два стора — (1) иммутабельная память персоны (конституция + корпус, не меняется), (2) мутабельная память про пользователя (наблюдения, профиль, прошлые советы, с провенансом). Персонаж «эволюционирует» только в сторе 2; голос фигуры фиксирован в сторе 1.** Это не даёт контексту пользователя испортить голос фигуры.

**Оценка верности** (одолжить методы): InCharacter, RPEval (arXiv 2505.13157), CharacterBench, PersonaEval. Curated: https://github.com/Neph0s/awesome-llm-role-playing-with-persona

## Ось 3. Мульти-агентная оркестрация и дебаты

**Основа:** Du et al. (MIT/Google, ICML 2024, T1, arXiv 2305.14325) — агенты независимо отвечают, N раундов читают чужое и сходятся. Заявлен прирост на математике/рассуждении. **Читать через контрарную линзу ниже, не до неё.**

**Фреймворки:** AutoGen (Microsoft, T1) — всё через разговор агентов, `GroupChat` + `GroupChatManager` (выбор спикера → ответ → broadcast). **Society of Mind агент** (AutoGen) — внутри group chat, снаружи ОДИН агент = «совет спорит внутри, пользователь видит один синтез». Прямо под твой кейс. CrewAI (роли), LangGraph (граф, контролируемый модератор-луп, масштаб линейный).

**Паттерн Karpathy LLM Council** (T1 репо, 20k звёзд) — чистейший блюпринт: (1) независимые первые мнения; (2) **review с анонимизацией** («Response A/B/C», чтоб не было фаворитизма) + ранжирование; (3) **Chairman** синтезирует. Переиспользуемые механики: анонимный кросс-ревью + отдельный синтезатор. (Сам автор: «vibe-coded хак», бенчмарка нет.) https://github.com/karpathy/llm-council

**Паттерн «синтезатор в свежем контексте»** (T2): критики параллельно, синтезатор в ЧИСТОМ контексте читает их как ДАННЫЕ, не как хвост своего разговора. Не якорится на своей реплике. Может встать на сторону меньшинства, если его логика сильнее.

**Модератор тюнит консенсус vs диссент:** «Consensus-Builder» двигает к согласию, «Neutral» сохраняет несогласие. Принуждать реальное несогласие: dissent-квоты, novelty-gates, counterfactual-промпты, секция «что ты теряешь» (цена игнора меньшинства).

### Контрарное (самое важное для решения)
- **«More Agents Is All You Need»** (T1, arXiv 2402.05120): простой sampling + majority-vote догоняет/бьёт сложные дебаты дешевле. Много «пользы дебатов» = просто ансамблирование.
- **«Can LLM Agents Really Debate?»** (T1, 2511.07784): решают силу рассуждения + разнообразие группы, а структурные ручки (порядок ходов) дают мало.
- **Парадоксальный спад** (T1, 2509.05396 / 2504.05047): больше раундов может СНИЗИТЬ качество (error propagation, over-revision). «Debate only when necessary.»
- **Sycophancy/конформизм** (T1, 2509.23055): модели бросают СВОЁ верное рассуждение ради мнения большинства; гетерогенные группы сходятся на неверном вместе; жёсткий конформизм ~29%, преимущественно вредный (57–77% флипов верное→неверное).
- **MAST taxonomy** (UC Berkeley, T1, arXiv 2503.13657): 14 failure modes, ~42% плохая спека, ~37% рассогласование агентов, ~21% слабая верификация. Прирост MAS над одиночным агентом часто минимален.

**Вывод (~80%):** council помогает когда (a) персоны реально разные, (b) есть судья/модератор, (c) раундов мало и адаптивно, (d) анонимизация + сохранение диссента против sycophancy. Иначе платишь 4–18× компьюта за уверенный НЕВЕРНЫЙ консенсус. **Сначала побей дешёвый baseline (sampling+majority-vote), потом добавляй дебаты.**

## Ось 4. Режимы и приёмы (с реальными зубами или без)

**Доказательно (ядро, можно защищать claim):**

1. **Дебаты / Devil's Advocate / Dialectical Inquiry** — T1 мета-анализ Schwenk 1990 (OBHDP 47(1)): и DA и DI дают выше качество решений и допущений, чем консенсус/эксперт. DA атакует рекомендацию, DI строит два полных противоположных плана из конфликтующих допущений → синтез. ⚠️ «DI лучше DA» НЕ устаканено. Реальная корректировка: триада «тезис-антитезис-синтез» — НЕ Гегель (он звал это «безжизненной схемой»), а Фихте/Халибеус. Не маркируй «гегельянской».

2. **Pre-Mortem (Klein, HBR 2007)** — T1 механизм. Шаги: (1) бриф; (2) «проект ПРОВАЛИЛСЯ, эффектно» (прошедшее время — ключевой ход); (3) каждый НЕЗАВИСИМО и молча пишет причины; (4) round-robin по одной без повторов; (5) усиление плана. Эффект «прозрачного заднего числа» +30% к идентификации причин — из Mitchell/Russo/Pennington 1989, НЕ из трайла самого премортема. Цитировать точно. Лучший режим «останови мою ошибку».

3. **Delphi + Nominal Group** — T1/T2. Delphi (RAND, 1951): анонимные эксперты, раунды, статистическая агрегация; анонимность убивает доминирование/бэндвагон. NGT: молчаливая независимая генерация → round-robin → кларификация → приватный ранкинг. Реплицированный эффект: **независимая генерация бьёт живой брейнсторм.** **Твоё структурное преимущество: AI может обеспечить настоящую независимость (раздельные контексты), которой люди не могут — полное убийство якорения.** Есть конвергентный prior art: «Scalable Delphi: LLMs for Structured Risk Estimation» (arXiv 2602.08889) — проверить.

**Сильные UX-слои (популярно, доказательства слабее — не переобещать):**

4. **Six Thinking Hats (де Боно)** — T2. 🔵 процесс/фасилитатор, ⚪ факты, 🔴 эмоция (без обоснования), ⚫ риски, 🟡 оптимизм, 🟢 креатив. Весь совет проходит каждую шляпу последовательно. Отличный UI-скелет, но НЕ доказательное ядро.

5. **Coaching / Advising / Challenging — стойка на ход** (самый product-shaped финдинг). Advise (скажи мне), Coach (Сократ через GROW: Goal→Reality→Options→Will), Challenge (оспорь мои допущения). Generation effect (учишься лучше, когда сам генеришь ответ) — T1; обёртка GROW — T2. Ортогонально режимам фасилитации, ставится по-ходово.

**Линзы, не режимы фасилитации** (оверлей на персону): Eisenhower (⚠️ не он изобрёл, Кови построил 2×2), second-order thinking, inversion Мангера (≈ pre-mortem, корень у Якоби), Bayesian updating (теорема T1, дисциплина — нет). Bayesian = слой калибровки/неопределённости.

## Ось 5. Риски и защиты

**1. Sycophancy (#1 враг).** RLHF оптимизирует под предпочтение людей; люди предпочитают приятное верному. Усиливается ПОСЛЕ preference-тюнинга. T1: Sharma et al. Anthropic (arXiv 2310.13548); **Cheng et al. Science 2026 (arXiv 2510.01395)** — AI аффирмит действия на 49% чаще людей; на r/AITA аффирмит в 51% случаев где человеческий консенсус 0%; одна сикофантная интеракция снижает готовность чинить конфликт и усиливает убеждённость в своей правоте; и именно льстивую версию юзеры зовут более качественной и хотят переиспользовать. ELEPHANT (arXiv 2505.13995): модели говорят ОБЕИМ сторонам морального конфликта что они правы в 48% случаев.
**Защиты:** (1) несогласие = ФИЧА персоны, не баг («эта фигура известна резким контраризмом; если юзер неправ по её фреймворку — скажи»); (2) steering > промпт-фиксы (промпт-митигации слабые); (3) devil's advocate проход как sycophancy-gate; (4) развязать engagement-метрики от reward-лупа, мерить «challenge rate»; (5) запретить аффирмить обе стороны.

**2. Persona drift.** T1 Jang et al. (arXiv 2412.00804): на 9 LLM — крупные модели дрейфуют БОЛЬШЕ; назначить персону недостаточно. ⚠️ «>30% после 8–12 ходов» широко повторяется, но к одному T1-замеру не привязано — направление верно, число не цитировать.
**Защиты:** периодическая ре-инъекция персоны (до 8-го хода); якорь в retrieval, не только в системном промпте; drift-детектор (embedding distance к эталону); не считать сильнейшую модель самой верной — тестировать дрейф по-модельно; «пересаживать» персону на границах сессий.

**3. Галлюцинированная атрибуция.** Фабрикация цитат с приписыванием реальному человеку (18–95% по модели). T1 обзор: https://www.mdpi.com/2673-2688/6/10/260
**Защиты:** (1) **жёсткое правило: кавычки + атрибуция ТОЛЬКО из верифицированного корпуса**, generate-then-verify пост-чек каждой цитаты; (2) **маркеры верности** — 🔵 sourced («Мангер писал в [Almanack]…», только из корпуса с цитатой) vs 🟡 inferred («Мангер-стайл прочтение твоей ситуации…», явно экстраполяция модели); (3) RAG по реальным текстам; (4) abstention: «у меня нет документированной позиции X по этому» вместо конфабуляции.

**4. Проекция vs верность / антропоморфизм.** Sycophancy + тонкая персона → персона отражает допущения ЮЗЕРА под именем фигуры. Антропоморфизм усиливает парасоциальное доверие и эхо-камеру. T1-якорь — dependence из Cheng et al.
**Защиты:** маркеры верности (двойная польза); обязательная секция «где фигура бы тебя оспорила»; постоянное раскрытие статуса симуляции в UI и в голосе персоны; осторожно с «я тебя помню» (углубляет парасоциальность); guardrails для уязвимых тем (mental health/деньги/медицина).

**5. Этика/право симуляции реальных (особенно живых).** ⚠️ ~60%, юрисдикция-специфично, не юр-совет. Живые публичные фигуры РИСКОВАННЕЕ мёртвых (активное право на публичность + диффамация). Right of publicity (US, лоскут штатов); NO FAKES Act (H.R.2794, ещё не закон, но указывает курс, $5000/нарушение); EU AI Act Art.50 — **обязательное раскрытие, что контент AI-сгенерён**.
**Защиты:** consent/лицензия от живых (и маркетинговый актив «официальная персона»); постоянное раскрытие симуляции (одна мера, три выигрыша); анти-диффамация = анти-галлюцинация (маркеры + верифицированные цитаты); не давать персонам «эндорсить» продукты/сделки; механизм takedown.

**6. Оверрелайанс / automation bias.** T1 (PMC10547752): смещённые AI-рекомендации сдвигают решения, и люди ПРОДОЛЖАЮТ повторять ошибки AI после его отключения.
**Защиты:** cognitive forcing (юзер фиксирует СВОЮ позицию ДО показа совета — ровно твой Productive Failure); показывать несогласие персон (мульти-персона = сама по себе защита, если НЕ усреднять диссент); фрейм «как Мангер бы тебя оспорил» > «вот что делать»; никакой автономии в high-stakes.

### 4 контроля, каждый гасит несколько рисков
| Контроль | Что гасит |
|---|---|
| Маркеры верности (🔵 цитата / 🟡 экстраполяция) | #3 атрибуция, #4 проекция, #5 диффамация, #6 ложный авторитет |
| Постоянное раскрытие «это симуляция» | #4 антропоморфизм, #5 AI Act + публичность, #6 оверрелайанс |
| Несогласие-как-фича + devil's advocate gate | #1 sycophancy, #4 эхо-камера, #6 automation bias |
| RAG по реальному корпусу + abstention | #2 drift, #3 галлюцинация, #5 диффамация |

## Извлечённый рецепт для скилла

1. **Профиль персоны** = поля Character Card V2 (`description`, `personality`, `mes_example`, `system_prompt`, `post_history_instructions`) + **конституция ~10 строк от первого лица** (Open Character Training).
2. **Голос** через `mes_example` few-shot реальными цитатами из корпуса + конституция.
3. **Позиции/факты** через RAG (или `character_book` keyword-записи если корпус < 200k токенов — без вектор-БД).
4. **Цитат-дисциплина:** grounding CoT + «цитата перед ответом» + inline `[источник, год]` + маркеры верности 🔵/🟡.
5. **Два стора памяти:** фиксированная персона + эволюционирующие наблюдения о пользователе (с провенансом, MemoryBank-стиль).
6. **Поведенческие правила** в `post_history_instructions` (сильнее системного промпта).
7. **Council-движок:** независимые первые мнения → анонимный кросс-ревью → адаптивные раунды (1–2, эскалация только при несогласии) → синтезатор в свежем контексте (может встать за меньшинство) → сохранение диссента (квота + «что теряешь»). Сначала побить majority-vote baseline.
8. **Режимы:** ядро доказательное — Дебаты/DA-DI, Pre-Mortem, Delphi/NGT; UX-слои — Six Hats, стойка Advise/Coach/Challenge; линзы — inversion/second-order/Bayesian.
9. **Sycophancy-дефолты:** несогласие как фича, devil's advocate gate, cognitive forcing (фиксируй гипотезу первым), challenge-rate метрика.

## Открытые проверки перед продом
- Точные effect sizes Schwenk 1990 (только абстракт) и первичка Mitchell 1989 «+30%».
- Юр-валидация (right of publicity, NO FAKES, EU AI Act) — нужен юрист.
- «Scalable Delphi» arXiv 2602.08889 — конвергентный prior art, прочитать.
- A/B council против sampling+majority-vote до заявления, что дебаты добавляют ценность.

## Архитектура памяти (несущая конструкция): union-mount, три слоя

Памятей не две, а **три**, и ключ в семантике монтирования. Модель = union mount / overlayfs.

**Слой 0 — память персоны (read-only, приватная советнику).** Корпус + конституция ~10 фраз от первого лица. Это «кто он». Примонтирован как RO-том, никогда не переписывается. Это «отдельная память» советника.

**Слой 1 — память отношений советник↔пользователь (read-write, приватная паре).** Что советник советовал, на чём настаивал, где пользователь проигнорировал и чем кончилось. Растёт. Своя у каждого советника.

**Слой 2 — общая память (пользователя/тандема, read-write пользователем).** Контекст, решения, проекты, CLAUDE.md / memory/. В неё монтируется.

### Асимметрия потока (иначе протекают риски из осей 3–5)
- Советник **читает** слой 2 при созыве (адаптивность, релевантность совета).
- Слой 2 **не пишет** в слой 0 (верность: контекст пользователя не разъедает голос фигуры → защита от проекции, риск #4).
- Советник **пишет** свободно в слой 1; в слой 2 — только через **гейт записи** (как pull request, не прямой push) с провенанс-меткой «по мнению {фигура}-персоны», не как факт.

Правило: нижний слой RO, верхние RW, запись не протекает вниз. Это разрешение противоречия верность↔адаптивность на уровне топологии памяти.

### Что дизайн даёт бесплатно
- **Портативность советника.** Слой 0+1 = экспортируемый бандл (как скилл). «Дай мне твоего Мангера с историей» = передача одной папки.
- **Изоляция при дебатах = анти-sycophancy между агентами.** На заседании каждому монтируется слой 2, но сторы слоя 1 друг друга советники НЕ видят. Это и есть условие анонимного кросс-ревью Карпатого: шаринг приватной памяти во время дебатов → дружный сход в неверный консенсус (контрарный риск оси 3). Монтируй общее, изолируй приватное.

### Adversarial-флаги (уровень 3)
1. **Протечка записи вниз** (слой 2 → слой 0) = главный риск, проекция. Защита: слой 0 жёстко RO.
2. **Прямая запись в слой 2 без гейта** = загрязнение памяти пользователя мнениями персон под видом фактов. Защита: гейт + провенанс.
3. **Стейл-монтирование.** Советник держит устаревший снимок контекста → советует по старой картине. Защита: монтировать свежим на каждую сессию, не кэшировать копию.

### Инфраструктурная задача (проектировать как компонент, не как концепт)
Физическая раскладка под Cowork / файловую память:
```
advisors/
  {name}/
    persona.md        ← слой 0: конституция + ссылки на корпус (RO)
    corpus/           ← слой 0: чанки/тексты фигуры (RO), или character_book
    relationship.md   ← слой 1: история советов с провенансом (RW, приватный)
    manifest.yaml     ← версия персоны, источники+tier, consent-статус, lens-набор
memory/  (общий)      ← слой 2: монтируется RO в сессию советника
council/
  sessions/{date}.md  ← лог заседаний, режим, состав, диссент, синтез
```
Открытые инфра-вопросы под проектирование: (a) механизм монтирования в Cowork (символический mount RO vs передача снапшота в контекст); (b) формат гейта записи слой1→слой2 (явный аппрув пользователя vs авто с меткой); (c) версионирование персоны при доливе корпуса (immutable core, append-only слой 1); (d) экспорт/импорт бандла советника между пространствами; (e) индексация corpus при <200k токенов (character_book без вектор-БД) vs больше (вектор-стор).
