# Спека: Само-документация Consilium-Principis (единый индекс → мануал + `explain_self`)

Дата: 2026-07-04. Статус: дизайн утверждён в брейнсторме, ждёт ревью юзера → план имплементации.
Контекст: проект крупный (42 тула, 64 скрипта, 88 тест-файлов) и растёт. Понимание устройства
разбросано по десятку файлов (README/QUICKSTART/CONNECT-MCP/SKILL.md/PROJECT-LOG/GLOSSARY/ARCHITECTURE
+ аудиты). Единой точки входа нет; рантайм-режима «объясни себя» нет. Любой ручной исчерпывающий
мануал протухнет — счётчик тулов уже гулял 33→37→42 по аудитам.

## Цель

Три работы из ОДНОГО источника правды, без взаимного дрейфа:
1. **Понять/довериться** — чужой открывает репо и за ~10 минут понимает «что это, как устроено,
   почему моат реален» (OSS-оценщик).
2. **Расширять** — разработчик видит архитектуру, где что лежит, как добавить тул/линзу/советника.
3. **Объяснять в рантайме** — юзер спрашивает у Консилиума «как ты работаешь / что делает X» и
   получает точный, прослеживаемый ответ.

## Несущие принципы (инварианты, не обсуждаются)

- **Единый источник правды.** Структурные факты (тулы, правила, рецепты, инвентарь) ГЕНЕРЯТСЯ из
  живого кода в один индекс. И мануал, и `explain_self` читают этот индекс — не расходятся.
- **Что меняется — генерится; что редко — пишется руками.** Churny-часть (тулы/правила/рецепты/
  скрипты) из кода; медленный нарратив («зачем», рационал моата, firewall, как расширять) — руками.
- **Тул возвращает факты, хост нарратит.** `explain_self` НЕ сочиняет прозу — отдаёт структурированные
  факты с `source_ref`. Хост проговаривает. Тот же принцип, что моат: verbatim-источник, ноль
  конфабуляции. Fail-closed на неизвестном запросе (честное «не нашёл, вот похожее»).
- **Оффлайн, zero-dep, в духе проекта.** Ни движка, ни сети, ни новых обязательных зависимостей.
  PDF — единственная опциональная внешняя зависимость (pandoc), и она никогда не блокирует.
- **Свежесть — тестом, не дисциплиной.** Гард-тест регенерит индекс и сверяет с закоммиченным; CI
  краснеет на дрейфе — ровно механизм `test_no_dark_tools.py`.

## Архитектура — 5 частей

```
живой код ──gen_selfdoc.py──▶ docs/selfdoc/index.json ──┐
(TOOLS, INSTRUCTIONS,                                    ├─▶ build_manual.py ─▶ docs/MANUAL.md (+ --pdf)
 recipes.json, scripts/*,        docs/selfdoc/           │
 tests/*, GLOSSARY.md)           narrative/*.md ─────────┴─▶ explain_self (MCP-тул, рантайм)
                                 (ручной нарратив)
                          test_selfdoc_fresh.py ◀── регенерит и сверяет (анти-дрейф)
```

### 1. Интроспектор `scripts/gen_selfdoc.py`

Вычитывает живой код → `docs/selfdoc/index.json` (машинный, коммитится). Разделы:
- `tools`: из `mcp_server.TOOLS` — `{name, description, input_schema, status}`, где `status` ∈
  {surfaced, internal} по 4-канальной логике `test_no_dark_tools.py` (INSTRUCTIONS / sibling-описание /
  recipes.json / реестр внутренних) + `referenced_in` (номера правил / id рецептов, где упоминается).
- `rules`: из `INSTRUCTIONS` — распарсить нумерованные правила 0..14 → `{n, title, text}`.
- `recipes`: из `recipes.json` — как есть.
- `scripts`: инвентарь `scripts/*.py` — `{path, subsystem, docstring_first_line}`; `subsystem` по
  каталогу/префиксу (engine, corpusbuild, collectors, eval, mcp, …). Модульный уровень, НЕ по-функционно.
- `tests`: карта `tests/test_*.py` — `{path, covers}` (подсистема из имени файла/первого докстринга).
- `glossary`: термины из `docs/GLOSSARY.md` (заголовок → определение), переиспользуя существующий файл.
- `meta`: `{tool_count, script_count, test_count, generated_from_commit?}` — числа, не хардкод.

DI для тестируемости: функции берут инъектируемый корень (`root=`), чтобы гонять на tmp-фикстуре.

### 2. Ручной нарратив `docs/selfdoc/narrative/*.md`

Медленно-меняющееся, интроспекцией не добываемое. Файлы (по одной теме — маленькие, фокусные):
- `00-overview.md` — что это и зачем (для слоя 1 мануала / `overview`).
- `10-moat.md` — рационал моата: тиры 🔵🟢🟡📐, fail-closed, двухфазный судья, почему verbatim.
- `20-firewall.md` — граница private↔public: advisors/* gitignored, PD-only ship, firewall_check.sh.
- `30-architecture.md` — 5-частная карта проекта, подсистемы, поток «вопрос → совет».
- `40-extend.md` — как добавить тул (TOOLS + handler + INSTRUCTIONS/recipe + тест), линзу, PD-советника.
Каждый файл — обычный MD; `explain_self` и `build_manual` читают их как есть.

### 3. Сборщик мануала `scripts/build_manual.py`

Сшивает нарратив + индекс → `docs/MANUAL.md`, три слоя (каждая аудитория читает до своей глубины):
- **Слой 1 «Обзор»**: `00-overview.md` + `10-moat.md` (суть).
- **Слой 2 «Архитектура»**: `30-architecture.md` + `20-firewall.md` + `40-extend.md` + сгенерённый
  инвентарь скриптов/тестов (из индекса).
- **Слой 3 «Справочник»**: полные таблицы тулов / правил / рецептов / глоссарий (из индекса).
- Хедер `MANUAL.md`: пометка «сгенерировано `build_manual.py` — правь нарратив/код, не этот файл».
- `--pdf`: если `pandoc` в PATH — экспорт `docs/MANUAL.pdf`; иначе печатает «поставь pandoc для PDF»
  и выходит 0 (никогда не падает, никогда не блокирует CI/сборку). MD — канонический артефакт.
- README получает ссылку на `docs/MANUAL.md`.

### 4. Рантайм-тул `explain_self` (в `mcp_server.py` TOOLS)

`explain_self(topic?)` — stateless, оффлайн, детерминированно. Читает `index.json` + нарратив.
- `topic` пусто / `overview` → обзор + 5-частная архитектура + точки входа.
- `tool:<имя>` → описание + схема + status + referenced_in.
- `rule:<N>` → текст правила.
- `recipe:<id>` → рецепт.
- `concept:<slug>` → нарратив-секция (moat/firewall/architecture/extend).
- `term:<слово>` → глоссарий.
- свободный текст → детерминированный best-match (подстрока/ключевые слова) по всем разделам;
  неоднозначно → вернуть кандидатов в `suggestions`.
- **Выход (render-agnostic):** `{kind:"self_explanation", topic, sections:[{title, body, source_ref}],
  see_also:[...], suggestions:[...]}`. `source_ref` = index-ключ или narrative-файл (прослеживаемость).
- **Fail-closed:** неизвестный topic → `sections:[]` + `suggestions:[ближайшие темы]`, exit-ok, без краха.
- Регистрируется в `TOOLS`; проводится в INSTRUCTIONS (новое правило или ветка Rule 9) — сам тул НЕ
  должен стать «тёмным» (гард `test_no_dark_tools.py` это проверит).

### 5. Гард-тест `tests/test_selfdoc_fresh.py`

Регенерит индекс в памяти и сверяет с закоммиченным `index.json` (либо покрытие: каждый `TOOLS`-ключ,
каждое правило 0..14, каждый рецепт, число скриптов/тестов присутствуют). Дрейф → CI краснеет,
заставляет пересобрать. Тот же механизм, что `test_no_dark_tools.py`.

## Поток данных

**Сборка (мейнтейнер):** правит код или нарратив → `python scripts/gen_selfdoc.py` (обновляет
`index.json`) → `python scripts/build_manual.py [--pdf]` (обновляет `MANUAL.md`) → коммит.
**Рантайм (юзер):** «как ты работаешь / что делает situation_analyze» → хост зовёт
`explain_self(topic)` → получает факты с `source_ref` → проговаривает человеку.
**CI:** `test_selfdoc_fresh.py` ловит забытую регенерацию.

## Ошибки / гейты (всё fail-closed)

- `explain_self` на неизвестном topic → честные `suggestions`, не выдумка, не краш.
- `gen_selfdoc` на кривом INSTRUCTIONS/recipes → падает громко на сборке (не молча пустой индекс).
- `index.json` отсутствует/битый при вызове `explain_self` → `{kind:"self_explanation", sections:[],
  suggestions:["запусти gen_selfdoc"]}` — деградация, не краш.
- `--pdf` без pandoc → сообщение + exit 0, MD уже собран.
- Дрейф индекса ↔ код → `test_selfdoc_fresh.py` красный.

## Тестирование (оффлайн, CI-инвариант цел)

Всё без сети/движка (`HEPHAESTUS_ENGINE=/nonexistent OLLAMA_HOST=…`):
- `gen_selfdoc`: на tmp-фикстуре кода → индекс содержит ожидаемые тулы/правила/рецепты; DI-корень.
- `build_manual`: индекс+нарратив → MD с тремя слоями; `--pdf` без pandoc → exit 0 + сообщение.
- `explain_self`: `overview` / `tool:<имя>` / `rule:<N>` / `concept:moat` / `term:<слово>` → верные
  секции с `source_ref`; неизвестный topic → пустой + suggestions; битый индекс → деградация.
- `test_selfdoc_fresh`: регенерённый индекс == закоммиченный (покрытие тулов/правил/рецептов/чисел).
- `explain_self` НЕ в списке тёмных (`test_no_dark_tools.py` зелёный).

## Firewall

- Всё в индексе/мануале — публичная машинерия (тулы, правила, рецепты, PD-нарратив). Ноль приватного:
  `gen_selfdoc` читает только tracked-код и shippable-файлы, НЕ `advisors/*`, НЕ `principis.md`, НЕ
  `gov_heads.local.json`. Нарратив пишется на PD/общих примерах.
- `firewall_check.sh` уже на страже push; новые файлы (index.json, MANUAL.md, narrative/) — публичные.

## Scope и фазы

- **MVP:** интроспектор + нарратив (5 файлов) + сборщик мануала (MD, --pdf опционально) + `explain_self`
  + гард-тест. Проводка `explain_self` в INSTRUCTIONS. Ссылка из README.
- **Отложено (YAGNI):** пер-функционный инвентарь; авто-диаграммы (graphviz); i18n мануала; веб-рендер;
  авто-регенерация индекса в pre-commit хуке (пока — ручной запуск + CI-гард).
- Ветка `feat/self-documentation`, адверсариальное ревью высокориск-частей (интроспектор парсинга
  INSTRUCTIONS, `explain_self` fail-closed) + финальное whole-feature ревью перед мержем. Оффлайн-CI.

## Риски / открытые вопросы

- **Парсинг INSTRUCTIONS хрупок** (два конкатенированных `%`-форматируемых литерала, правила 0..14
  свободным текстом). Митигация: парсер на регексе номеров правил + гард-тест, что все 0..14 захвачены;
  при непарсинге — громкий fail, не тихая пропажа.
- **Нарратив всё равно надо поддерживать руками** — но он медленный (моат/firewall/архитектура меняются
  редко), и его немного (5 фокусных файлов). Дрейф нарратива код не ловит — это осознанный компромисс.
- **`sheaf-admm` (arXiv 2605.31005, ICML 2026) — НЕ применяем.** Проверено: ML-пайплайн для vision/
  puzzle с дифференцируемым training-loop; для нашей символической «единый источник + генерация»
  задачи — keyword-only (склейка локального в глобальное совпадает лишь по названию). Оставлено как
  концептуальная параллель, не метод.

## Критерий успеха

Чужой человек на GitHub за ~10 минут по `docs/MANUAL.md` понимает что это/как устроено/почему моат
реален (слой 1-2), а поставив MCP — спрашивает `explain_self` и получает точный прослеживаемый ответ
про любой тул/правило/концепт. Мейнтейнер добавляет тул → `test_selfdoc_fresh` краснеет, пока не
пересобран индекс → документация не отстаёт от кода ни на коммит.
