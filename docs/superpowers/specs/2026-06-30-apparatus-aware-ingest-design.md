# Apparatus-aware ingest — дизайн

**Goal:** При добавлении мыслителя из книги (PD-том) сервер сам распознаёт редакторский
аппарат (вступление переводчика, инлайновый комментарий толкователей, приложения) и **не
запекает его как слова автора**. Дефолт — разметка тирами (автор 🔵, комментарий 🟢), без
блокирующего выбора; правка одной фразой и обратимо; ноль ollama.

**Architecture (1 строка):** Новый чистый детерминированный модуль `corpusbuild/apparatus.py`
(scan + clean + split_inline) + реестр детекторов; `add_source` авто-применяет дефолт-режим и
возвращает дружелюбную сводку с опциональными правками; ingest размечает инлайн-комментарий
тирами при флаге в манифесте. Режим — переключаемое свойство источника (пересборка из сырого
файла, недеструктивно).

**Tech stack:** Python 3.10+, stdlib только (re). НЕТ ollama, НЕТ сети в самом модуле.

---

## Контекст (зачем)

Энд-ту-энд прогон 2026-06-30: `add_source(url=gutenberg «Искусство войны», tier=P1)` залил **весь
файл** издания Джайлса как P1 → 🔵. Замер корпуса (431 чанк): 78% содержат `[…]`-комментарий
толкователей, 57% явно называют Чжан Юя/Цао Куна/Ту Му, ~17% — похоже на чистого Сунь-Цзы. Запрос
«что Сунь-Цзы о хитрости» вернул как 🔵 слова **Чжан Юя** и анекдот про **Веллингтона** из
вступления. Гейт механически честен (дословный матч реален), но **курация источника лжёт об
авторстве** — для продукта про верность это худший класс дефекта. `strip_gutenberg` снимает только
PG-боилерплейт, не редакторский аппарат. Юнит-тесты этого не ловят (синтетические чистые корпуса).

## Не-цели (YAGNI)

- НЕ ollama-классификатор чанков (явно отвергнут: «минимум ollama» + недетерминизм → риск ложного 🔵).
- НЕ универсальный парсер любых изданий. v1 — скобочная конвенция (Giles/Legge/Loeb) + границы секций
  + лексикон толкователей. Небрекетный комментарий иной конвенции ловит хост-адъюдикация или попадает
  под консервативный fail-closed (вниз, не в 🔵).
- НЕ автоправка чужих корпусов задним числом. Только новый ингест через `add_source`.

## Решения (из брейншторма)

1. **Точка входа:** `add_source` сам детектит (одна точка), но **не блокирует** — авто-применяет
   дефолт и предлагает правку (улучшение «act-then-offer»).
2. **Детекция:** структурно-детерминированно + ризонинг ХОСТА на спорное, **0 ollama**, fail-closed
   вниз (трёхуровнево: уверенно автор→🔵, похоже на аппарат→🟢, непонятно→drop).
3. **Дефолт-режим:** `tier` (автор 🔵 + комментарий классиков 🟢; вступление/приложения отброшены).
4. **Режим переключаем** — свойство источника в манифесте, пересборка из сырого файла (недеструктивно).
5. **Детекторы — реестр**, расширяемый без переписывания.

## Компоненты

### `scripts/corpusbuild/apparatus.py` (новый, чистый, без ollama/сети)

```python
# Реестр детекторов: каждый — чистая ф-я text -> сигнал (или None). Расширяется добавлением в список.
DETECTORS = [detect_bracket_commentary, detect_named_commentators,
             detect_front_matter, detect_back_matter, detect_note_sections]

def scan(text: str) -> dict:
    """Детерминированный отчёт об аппарате. Возвращает:
    {
      "has_apparatus": bool,                 # сработал хоть один детектор выше порога
      "signals": {                           # СЛУЖЕБНОЕ (юзеру не показывать)
         "bracket_ratio": float,             # доля строк с [...]
         "commentator_hits": int,            # хиты лексикона толкователей
         "front_until": str|None,            # маркер-кандидат: конец вступления (строка)
         "back_from": str|None,              # маркер-кандидат: начало приложений
         "front_confident": bool,            # уверенность по границам
         "back_confident": bool,
      },
      "needs_host_review": bool,             # границы неуверенны → хост глазами подтверждает
      "sample_author": str,                  # 1 короткая строка похожего на автора
      "sample_apparatus": str,               # 1 короткая строка похожего на аппарат
      "suggested_mode": "tier",              # дефолт
    }"""

def strip_sections(text: str, front_until: str|None, back_from: str|None) -> str:
    """Срез фронт/бэк-материи: всё до front_until и от back_from. None → не резать с этой стороны.
    Это редакторская обёртка, не произведение → физически удаляется (честно). Общий для clean и tier."""

def clean(text: str, front_until=None, back_from=None) -> str:
    """Только слова автора: strip_sections + удалить инлайн [...]-спаны. Результат — чистый P1."""

def split_inline(text: str) -> list[tuple[str, str]]:
    """Режет строку по [...]: [(segment, role)], role ∈ {"author","commentary"}.
    Несбалансированная/вложенная скобка → роль "commentary" (fail-closed вниз, НЕ author).
    Пустые сегменты отбрасываются."""
```

**Инвариант fail-closed (критично для рва):** 🔵 присваивается ТОЛЬКО тексту, который (1) внутри
**уверенно-определённого тела** произведения И (2) **вне** `[…]`-спанов. Всё неуверенное → 🟢 (S1)
или drop, НИКОГДА P1:
- поля до первого уверенного авторского блока и после последнего (проза вступления/приложений,
  даже без скобок, при низкой уверенности границ) → 🟢, не P1;
- `[…]`-спаны, несбалансированные/вложенные скобки → 🟢;
- сработавшие детекторы аппарата на блоке → 🟢/drop.

В худшем случае недо-claim 🔵 (часть реального автора уйдёт в 🟢), но НИКОГДА не пере-claim
(аппарат не станет 🔵). Это и есть честность рва: 🔵 = «уверенно его слова», не «возможно его».

**Детекторы (структурные сигналы, без модели):**
- `detect_bracket_commentary` — доля строк с `[…]` выше порога (издания с инлайн-глоссами).
- `detect_named_commentators` — лексикон классических толкователей (Tu Mu, Chang Yu, Wang Hsi,
  Ts'ao Kung, Li Ch'uan, Mei Yao-ch'en, Chia Lin, Tu Yu, Ho Shih, Chang Yü…) + общие («the
  commentator», «glosses», «scholiast»).
- `detect_front_matter` — кандидат-маркер начала тела: первый заголовок главы (роман. цифры/
  «CHAPTER»/«I.»). Всё до него — вступление.
- `detect_back_matter` — маркеры приложений: `APPENDIX`, `BIBLIOGRAPHY`, `INDEX`, `FOOTNOTES`,
  `THE END` + библиографические хвосты.
- `detect_note_sections` — секции `NOTES`/`COMMENTARY` блоками.

### Манифест — расширение схемы (`sources/manifest.json`)

Существующее: `{ <source>: { tier, regions?, attribution?… } }`. Добавляем на источник:

```jsonc
{ "art-of-war.txt": {
    "tier": "P1",
    "apparatus": {
      "mode": "tier",                  // tier | clean | raw — переключаемо
      "front_until": "I. LAYING PLANS", // подтверждённые границы (хостом или scan)
      "back_from": "APPENDIX",
      "inline_commentary": "bracket",   // флаг для ingest: размечать [...] как 🟢
      "detectors": ["bracket_commentary","named_commentators","front_matter"]
    }
} }
```

`mode=raw` → старое поведение (весь файл tier). `validate_manifest` доучивается проверять
`apparatus.mode ∈ {tier,clean,raw}` и что `front_until`/`back_from` реально встречаются в тексте.

### `add_source` (mcp_server) — изменения

Новые параметры: `mode` (`"auto"`(дефолт)|`"tier"|"clean"|"raw"`), `front_until`, `back_from`
(хост-оверрайды границ).

Поток:
1. fetch (как сейчас, SSRF-pinning) → `strip_gutenberg` → `apparatus.scan`.
2. `mode="auto"`:
   - `has_apparatus=False` → как сейчас: land raw, манифест `tier=P1, apparatus.mode=raw`.
   - `has_apparatus=True` → **авто-применить `tier`** (улучшение 1, не блокировать): записать манифест
     `mode=tier, inline_commentary=bracket, front_until/back_from из scan`. Вернуть сводку +
     опциональные правки (не ворота).
3. `mode∈{tier,clean,raw}` (явный, для правок) → применить соответственно:
   - `tier` → манифест над сырым файлом + `inline_commentary=bracket` + границы.
   - `clean` → записать `<name>.clean.txt = apparatus.clean(raw, front_until, back_from)`; манифест
     `tier=P1` над чистым файлом; сырой `<name>.txt` сохранить (реверс).
   - `raw` → весь файл P1 (осознанный отказ от чистки).
4. Возврат (для не-тех юзера хост показывает `hint`, не сырой dict):

```jsonc
{ "ok": true, "advisor_dir": "...", "source_file": "art-of-war.txt",
  "mode": "tier",
  "hint": "Добавил источник Сунь-Цзы. Его слова помечу 🔵, толкования классиков — 🟢, вступление и приложения отброшу.",
  "adjustments": [          // опциональные правки натуральным языком (НЕ ворота)
     {"phrase": "только его слова",      "mode": "clean"},
     {"phrase": "оставь и комментарии как есть", "mode": "raw"}
  ],
  "needs_host_review": false,  // true → хост глазами уточняет границы и зовёт add_source(front_until=…, back_from=…)
  "next_action": "build_advisor(advisor_dir)" }
```

`needs_host_review=true` (низкая уверенность границ): хост (Claude) смотрит строки-кандидаты в
`report.signals` и подтверждает/задаёт `front_until`/`back_from`. Если хост не может — **консервативный
fail-closed**: брать только уверенно-авторское (инлайн-разметка остаётся, секции с низкой уверенностью
→ 🟢, не P1), и `hint`: «взял ядро его слов; если есть чистый текст — вставь, помечу всё как его».
Юзер никогда не застревает.

### Ingest — разметка инлайн-комментария (`corpusbuild/ingest.py` + `clean.py`)

При сборке, если у источника `apparatus.inline_commentary == "bracket"`:
- **границы секций:** если `front_confident`/`back_confident` — секции **физически срезаются**
  (`strip_sections`, в корпус не идут); если неуверенно — секция-поле **остаётся, но тегается `S1`
  (🟢)** через `regions` манифеста (не P1) — реализует «неуверенные поля → 🟢, не 🔵»;
- **инлайн:** каждый ингест-рекорд тела `(loc, text)` прогоняется через `apparatus.split_inline` →
  сегменты с ролью; `role=author` → `P1` (🔵), `role=commentary` → `S1` (🟢);
- чанкинг не склеивает сегменты разных тиров (как уже не склеивает регионы).

То есть тиры собираются из двух уровней: регионы (секции тела/полей) задают базовый тир строки,
`split_inline` понижает скобочные части до `S1`. `apply`-шаг `add_source` пишет в манифест либо
срез-границы (уверенно), либо `regions` с `S1`-полями (неуверенно). Если `mode=clean`/`raw` или нет
флага — ingest без изменений.

## Поток данных целиком (happy path, tier-дефолт)

```
add_source(url=gutenberg art-of-war)         юзер: «добавь Сунь-Цзы»
  → fetch + strip_gutenberg
  → apparatus.scan → has_apparatus=true, границы уверенны
  → манифест: mode=tier, inline_commentary=bracket, front_until/back_from
  → возврат {hint:"его слова 🔵, толкования 🟢…", adjustments, next_action:build}
хост: build_advisor(advisor_dir)             (как сейчас, фоновый job)
  → ingest: срез секций; split_inline → автор P1, скобки S1
  → corpus.jsonl: 🔵 = Сунь-Цзы, 🟢 = классики; вступление/приложения отсутствуют
хост юзеру: «Сунь-Цзы готов. 🔵 его слова, 🟢 толкования классиков. Хочешь только его — скажи «только его слова».»
```

**Правка (обратимо):** юзер «только его слова» → хост `add_source(source_file=…, mode=clean)` →
`build_advisor` → корпус только 🔵. Сырой файл цел, можно вернуть `tier` обратно.

## Обработка ошибок / «никогда не застрять»

- Границы неуверенны → `needs_host_review`; хост уточняет границы. Нет хоста → консервативный
  fail-closed: 🔵 только уверенно-авторскому ядру, **неуверенные поля до/после ядра → 🟢, не P1**
  (даже если в них нет скобок).
- `front_until`/`back_from` не найдены в тексте → не резать ту сторону (валидатор предупреждает),
  fail-closed: вместо среза неуверенное поле помечается 🟢 (S1), а не остаётся P1 — проза
  вступления никогда не становится 🔵.
- Несбалансированные скобки в `split_inline` → роль commentary (вниз).
- Не-PD хост / SSRF / traversal — без изменений (существующие гарды), переводятся хостом (rule 9).

## Тестирование (детерминированно, без ollama/сети)

Фикстура `tests/fixtures/giles-like.txt` — мини-«издание»: вступление (Веллингтон-абзац) +
2 «главы» с авторскими строками и инлайн `[Commentator says: …]` + приложение.

- `apparatus.scan` → `has_apparatus=true`, верные `front_until`/`back_from`, осмысленные сэмплы.
- `apparatus.clean` → скобки удалены, вступление/приложение срезаны, авторские строки целы.
- `apparatus.split_inline` → корректная сегментация автор/комментарий; вложенные/несбалансированные
  скобки → commentary, не падает.
- e2e tier: build на фикстуре → авторские чанки `P1`/🔵, скобочные `S1`/🟢, вступление/приложение
  в корпусе отсутствуют.
- e2e clean: build → только авторские `P1`, комментарий и секции отсутствуют.
- **fail-closed:** спорный спан/низкая уверенность → НЕ `P1` (проверка инварианта рва).
- `add_source mode=auto` с аппаратом → `mode=tier` в манифесте + `hint` + `adjustments`, не блокирует.
- `add_source mode=clean` → пишет `.clean.txt`, сырой файл сохранён, манифест P1 над чистым.
- Переключение tier↔clean пересборкой → недеструктивно (сырой файл тот же).
- `validate_manifest` ловит `mode` вне набора и отсутствующие в тексте маркеры.
- **Регрессия на реальном Сунь-Цзы** (опц., локально): tier-режим → доля 🔵 схлопывается к
  авторскому ядру, комментаторы → 🟢, Веллингтон-вступление исчезает.

## Подача не-тех юзеру (INSTRUCTIONS)

Новое правило (rule 10): когда `add_source` вернул `mode=tier/clean` с `hint`/`adjustments` —
хост сообщает простым языком, ЧТО будет помечено как чьи слова (🔵 автор / 🟢 толкователи), и
предлагает правки фразой, **не как обязательный выбор**. Сырые `signals`/доли/маркеры не
показывать (rule 9). На `needs_host_review` — хост сам сверяет границы по строкам-кандидатам,
у юзера не спрашивает технических вопросов; если просит — то по-человечески («в книге есть
длинное предисловие переводчика — отбросить его? (да/оставить)»).

## Декомпозиция реализации (для writing-plans)

1. `apparatus.py`: `scan` + детекторы (реестр) + `strip_sections` + `clean` + `split_inline` + юнит-тесты.
2. Ingest-интеграция: `split_inline` при `inline_commentary=bracket`; срез секций; тесты e2e tier/clean.
3. Манифест-схема + `validate_manifest` + `build_lens`/`add_source` запись `apparatus`.
4. `add_source` поток `mode=auto/tier/clean/raw` + `hint`/`adjustments`/`needs_host_review`; тесты.
5. INSTRUCTIONS rule 10; обновить CONNECT/README кратко.
6. Регрессия на реальном Сунь-Цзы (локальная проверка).
